## 四、技术现实事实表（来自 R1-R4 工程师 agent + WebSearch 实证）

### 4.1 Koma 现有架构现状

| 项 | 真实数据 |
|---|---|
| TaskService 默认并发 | **4**（无 worker 池） |
| ffmpeg.ts 行数 | 976 行（无硬件加速代码） |
| SQLite | WAL 已开，无跨项目向量索引 |
| Provider 抽象 | LLM/TTI/ITV/TTS/image-hosting 5 类 |
| ed25519 签名 | 仅用于 release 验签 |
| 处理 80GB ProRes | 主进程 spawn 同步监听 → **阻塞 UI 50-300 秒** |
| 单项目 50 万 shot | 跨表 transaction → **SQLITE_BUSY 风暴** |
| 插件 SDK | 不能直接调 ffmpeg / TaskRunner / 数据库 |
| AAF / XML / EDL / OTIO | **无** |

## 九、4 轮各 agent 共识与分歧

### 共识点（4 轮独立得出相同结论）

1. **3 个场景是真共识**：预告片 / 横竖屏 / 多语言 ——A/B/C 三个角色独立打分都最高
2. **替换路径 > 重生成路径**：所有工程师角色都明确这一点
3. **基于现有 Electron + ee-core 架构扩展可行**：4 轮 C 角色都确认
4. **法务由影视公司自负**是关键前提
5. **C2PA 双标识 + KYC + 名单审核**是工具方必做兜底

### 主要分歧点

| 分歧 | A 立场 | B 立场 | C 立场 | D 立场 | 用户决策 |
|---|---|---|---|---|---|
| 场景数量 | 想做 7-9 | 跟随设计 | 评 3-4 可工业级 | 砍到 1-2 | **7 场景** |
| 主演特写换脸 | 接 | 设计 UI | 评 90-94% | 零成功率 | **接** |
