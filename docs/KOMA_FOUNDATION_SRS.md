# Koma 底层系统需求规格说明书 (SRS)

> 文档范围：Koma 桌面端"底层 → 上层业务"的支撑骨架。
> 覆盖七大子系统：底层规划 / 持久化存储 / 文件存储 / 后台任务 / 插件系统 / 系统数据管理 / 主题系统。
> 描述方式：以"系统应当具备的能力"为单位组织（What + 为什么 + 边界），不夹杂代码片段、不引用历史版本、不写迁移路径。
> 阅读对象：参与重构的研发、QA、架构评审。

---

## 0. 名词与统一约定

| 术语 | 含义 |
|---|---|
| **业务根目录 (Business Root)** | 应用拥有的、与 Electron 框架数据隔离的根目录，所有业务数据落在此处 |
| **运行时存储根 (Runtime Storage Root)** | 用户可重定向的"项目数据根"，缺省等于业务根，可指向外置硬盘/网盘挂载 |
| **项目 (Project)** | 一个完整的创作工程，拥有独立的 SQLite、独立的媒体目录、独立的缓存目录 |
| **全局数据 (Global Data)** | 跨项目共享的系统数据：渠道凭证、应用偏好、聊天历史、任务记录、插件清单等 |
| **资产 (Asset)** | 落盘的媒体文件（图/视频/音频），数据库中只存元数据与路径 |
| **任务 (Task)** | 一次具有生命周期的后台执行单元（生成、上传、转码、分析等） |
| **能力 (Capability)** | 由内置模块或插件提供、可被统一调度的功能单元（如某个 LLM 模型、某个 TTS 音色） |
| **渠道 (Channel)** | 一组供应商凭证 + 模型清单 + 配置（如"我的 OpenAI 账号"） |
| **Scope** | 数据归属域，分为 `global` / `project:<id>` / `chat:<sessionId>` |

## 1. 底层规划（应用骨架）

### 1.1 应用进程模型

**SRS-1.1.1** 系统必须为单实例桌面应用。当用户重复启动时，第二个实例应自动退出并请求第一个实例恢复主窗口到前台。

**SRS-1.1.2** 系统使用主进程 + 渲染进程的双进程架构：
- 主进程承担：文件 I/O、SQLite、网络请求代理、自定义协议、后台任务调度、插件运行时、自动更新、签名校验。
- 渲染进程承担：UI 渲染、用户交互、LLM 流式响应处理、复杂业务逻辑（脚本分析、分镜分析）。
- 两进程之间唯一通信通道为受控的 IPC，不允许渲染进程直接访问 Node 能力。

**SRS-1.1.3** 渲染进程必须在上下文隔离（contextIsolation）模式下运行，关闭 nodeIntegration。所有暴露给前端的能力只能通过 preload 桥定义的对象访问。

**SRS-1.1.4** 系统必须提供一致的窗口体验：
- 自定义无边框标题栏，前端控件实现最小化、最大化/还原、关闭。
- 跨平台差异（macOS 绿色按钮进全屏 vs Windows/Linux 最大化）需在 UI 层正确反映当前窗口状态。
- 默认窗口尺寸、最小尺寸、暗色背景在应用启动时即生效，避免白屏闪烁。

### 1.2 启动与生命周期

**SRS-1.2.1** 启动序列必须保证以下顺序：
1. 设置应用数据路径（与 Chromium 框架数据隔离）。
2. 注册自定义协议为"特权 scheme"（standard / secure / supportFetchAPI / stream / corsEnabled）。
3. 进入 `app.ready` 后创建主窗口、设置应用菜单。
4. 主窗口完成加载后，运行 preload 初始化：注册协议处理器、注入安全头、初始化 IPC 通道、启动子服务（任务恢复、版本迁移、自动更新、插件市场）。

**SRS-1.2.2** 系统必须监听以下生命周期事件并执行对应行为：
- 应用 ready：日志系统初始化。
- 窗口关闭：在 macOS 下不退出应用，仅隐藏窗口；其他平台退出。
- 应用关闭前：刷新 SQLite WAL checkpoint、关停所有任务的 Abort 信号、保存待落盘状态。
- 渲染进程崩溃：作为致命错误处理，触发应用退出（不允许悄悄复活产生数据不一致）。

**SRS-1.2.3** 开发模式必须暴露固定的 Chromium 远程调试端口（默认 9333，环境变量可覆盖），用于自动化 UI 验证；正式发布版本不暴露此端口。

### 1.3 IPC 契约

**SRS-1.3.1** 所有 IPC 通道必须在 preload 桥的白名单中显式列出，分为两类：
- 调用型（renderer → main，请求-响应）。
- 监听型（main → renderer，单向广播或事件流）。
不在白名单中的通道访问必须抛错并被前端拦截。

**SRS-1.3.2** 主进程暴露的能力按"控制器"组织（窗口、对话框、文件、应用、项目、灵绘、FFmpeg、网络、插件、更新、市场、诊断）。每个控制器的公共方法必须自动映射为统一命名的 IPC 通道（`controller/<file>/<method>`）。

**SRS-1.3.3** 系统必须提供 CI 级别的白名单对账脚本：扫描所有控制器的公共方法，与白名单逐项比对，发现缺失或孤儿立即失败构建。

**SRS-1.3.4** 主进程可以反向调用渲染进程（用于将 LLM 推理、Provider 快照等渲染端能力作为可调度任务的 handler）。该通路必须：
- 由渲染进程"认领" type（claim）后才能被路由。
- 多个渲染端时后认领者覆盖前者。
- 渲染端关闭时自动撤销认领并失败其所有挂起请求。
- 单次请求带可配置超时，默认 60 秒，长任务（媒体轮询）可独立放宽至 30 分钟。

### 1.4 自定义协议与本地资源访问

**SRS-1.4.1** 系统必须提供一个本地资源协议（命名为 `koma-local://`），用于在前端通过 `<img>` / `<video>` / `fetch` 访问业务目录下的文件，避免相对 `file://` 引发的安全和缓存问题。

**SRS-1.4.2** 协议处理器必须：
- 对请求路径做白名单校验，只允许下列根目录及其子路径：用户主目录、系统 appData / userData / temp、业务根、运行时存储根、应用资源目录、应用安装目录。
- 拒绝 `..` 越界，规范化后再校验。
- 支持 HTTP Range 请求（206 分块响应），用于视频拖拽进度。
- 根据扩展名映射 MIME 类型；未识别扩展返回通用二进制类型。
- 注入 CORS 头允许全域，方便 canvas / Web Audio 等场景。

### 1.5 网络代理与请求安全

**SRS-1.5.1** 渲染进程不允许直接 `fetch` 调用第三方 API（用于消费机密 Key 的场景）；必须经主进程的"网络代理"通道。

**SRS-1.5.2** 网络代理必须执行 SSRF 防护：
- 仅允许 `http` 与 `https`。
- 解析后的目标 IP 不得落在私有段（IPv4：127/8、10/8、172.16/12、192.168/16、169.254/16、0.0.0.0/8；IPv6：loopback、link-local fe80::/10、unique-local fc00::/7）。
- 必须在 DNS 解析后对结果 IP 二次校验，防 DNS 重绑定。

**SRS-1.5.3** 网络代理必须支持三种凭证注入模式，且互斥：
- Bearer：`Authorization: Bearer <key>`（默认）。
- Query Key：将 key 注入 URL 查询串指定参数名。
- Raw Authorization：直接以 key 作为 `Authorization` 头值。
请求方在调用代理时通过受控请求头声明使用哪种模式与哪条渠道，主进程查表解密后注入；明文 key 严禁出现在渲染进程。

**SRS-1.5.4** 网络代理必须实现两层重试：
- 连接级（socket / DNS 错误）按指数退避重试若干次。
- 响应级（HTTP 5xx、429、上游瞬时错误关键字）独立重试。
所有响应（含错误）以 Base64 透传给调用方，避免二进制内容编码失真。

**SRS-1.5.5** 网络代理必须支持 multipart 文件上传，并自动剥离所有内部追踪头（traceId / traceSource 等），确保不泄露到第三方服务。

### 1.6 内容安全策略 (CSP)

**SRS-1.6.1** 主窗口必须强制 CSP，并保证：
- `script-src` 限定为自源、必要的 `unsafe-inline`、`koma-local`；开发模式额外允许 `unsafe-eval`（HMR）。
- `connect-src` 仅允许已声明的 API 域名白名单 + 本机回环（用于本地模型/调试）。
- `img-src` / `media-src` 允许自源、`blob:`、`koma-local`、`https`、`http`（外部 CDN 缩略图）。
- `style-src` 限定为自源 + 必要内联 + 字体 CDN。

**SRS-1.6.2** 新增 API 渠道时，必须同步扩充 CSP 白名单；CSP 不允许放宽为 `*`。

### 1.7 自动更新

**SRS-1.7.1** 系统必须具备应用自动更新能力，对外暴露：检查更新 / 下载更新 / 立即重启安装 / 查询当前状态 四个动作。

**SRS-1.7.2** 更新状态机：`idle → checking → (idle | downloading) → (downloaded | failed)`。
- 任意时刻只允许一个"检查"或"下载"在途。
- 失败状态必须能够自动定时重试（缺省间隔 6 小时）。

**SRS-1.7.3** 更新 manifest 必须经过 ed25519 签名验证；除签名通过外还需校验：
- `releasedAt` 不超过 30 天（防过期 manifest 被回放）。
- 候选版本 ≥ 当前已安装版本（防降级攻击）。

**SRS-1.7.4** 平台策略：
- macOS：DMG 安装包，支持引导式安装或自动进度。
- Windows：exe / squirrel-windows / portable，按打包格式自动选择。
- Linux：AppImage / deb 提示用户手动安装。

**SRS-1.7.5** "立即安装"必须感知后台长任务：当存在未完成任务时，立即安装请求被静默忽略并保留下载结果，下次启动时自动完成升级。

### 1.8 诊断与日志

**SRS-1.8.1** 系统必须为多类日志独立成文件，至少包括：主进程业务日志、主进程错误日志、框架日志、渲染端业务日志、渲染端控制台快照。

**SRS-1.8.2** 日志必须满足以下约束：
- 单行最大长度受限（默认 24,000 字符），超长截断并标注。
- 单条结构化数据序列化后受限（默认 12,000 字符）。
- 单目录文件数量受限（默认 30 个，旧的轮转删除）。
- 单次导出文件大小受限（默认 20 MB）。

**SRS-1.8.3** 写入日志前必须自动脱敏：
- `Bearer xxx`、`sk-xxx`、`api_key=xxx` 等模式替换为 `[REDACTED]`。
- 结构化对象序列化时递归识别敏感键名（authorization、token、key、secret 等）。

**SRS-1.8.4** 系统必须提供：
- 日志列表与大小查询（供"设置 / 诊断"页展示）。
- 日志一键打包导出（zip）。
- 日志一键清空。

## 2. 持久化存储

### 2.1 双数据库分层

**SRS-2.1.1** 系统使用两个 SQLite 数据库，职责严格分离：
- **全局数据库**：跨项目共享，存储渠道凭证、应用偏好、聊天历史、任务记录。位于业务根固定路径，不随用户重定向项目根而移动。
- **项目数据库**：每个项目独有一份，存储该项目的所有业务数据（剧集、分镜、角色、场景、道具、资产元数据、时间线、灵绘工作区等）。位于项目目录下。

**SRS-2.1.2** 两个数据库都必须：
- 启用 WAL 模式以支持读写并发。
- 启用外键约束。
- 设置忙等超时（≥ 6 秒）以应对短暂锁竞争。
- 提供事务 API，所有"主表 + 关联表"组合写入必须包在事务内。

**SRS-2.1.3** 项目数据库的所有业务表必须以 `project_id` 为外键（或位于其级联范围内），删除项目时通过 `ON DELETE CASCADE` 自动级联清理。

### 2.2 Schema 版本管理与迁移

**SRS-2.2.1** 两个数据库各自维护一张 `schema_version` 元数据表，记录历次成功执行的迁移版本号。

**SRS-2.2.2** 启动时自动迁移流程：
1. 读取当前最大已应用版本。
2. 若低于目标版本，按版本号严格递增逐次执行迁移脚本。
3. 每次迁移在事务中执行，成功后插入版本记录；失败则整体回滚并阻止应用进入业务态。
4. 新建数据库直接生成目标版本的完整 Schema（不重放迁移历史）。

**SRS-2.2.3** 迁移脚本不支持自动回滚。重大版本升级前系统应提示用户做一次显式导出/备份。

### 2.3 项目数据库内容（业务实体）

**SRS-2.3.1** 项目数据库至少包含以下实体表：
- **项目元信息**：标题、类型（剧集 / 旁白）、状态、画幅、扩展元数据（TTS 音色、TTS 语速、视频时长候选集等）。
- **剧集**：集数、剧本就绪门控、分析结果 JSON。
- **角色 / 场景 / 道具**：名称、描述、提示词、内容指纹、本地预览路径、远端预览 URL。
- **分镜**：所属剧集、台词分段（数组形式，可按行/字幕块组织）、画面提示词、视频提示词、当前版本指针。
- **分镜版本**：版本号、图本地/远端、视频本地/远端、音频本地/远端。
- **分镜-角色 / 分镜-场景 / 分镜-道具**：多对多关联，带排序字段。
- **分镜媒体绑定**：参考图 / 生成图 / 视频 / 音频四个 slot，多对一关联到分镜。
- **资产**：媒体类型、本地路径、远端 URL、缩略图路径、MIME、宽高、时长、FPS、字节数、指纹、引用计数、来源（用户上传 / TTI / ITV / TTS / 风格库等）、来源任务 ID、渠道 / 模型 / 能力标签、原始响应 payload。
- **时间线**：作用域类型（项目 / 剧集）+ 作用域 ID + 帧率 + 分辨率，唯一约束。
- **时间线轨道 / 片段 / 过渡 / 关键帧**：完整时间线编辑数据。
- **灵绘工作区**：节点 / 连线 / 资产 / 执行日志；以及跨工作区的全局资产库与参考图。

**SRS-2.3.2** 所有"主体 + 多对多关联 + 媒体绑定"的保存必须以"先删后插"的方式在单事务内替换，保证关联表与主体一致。

**SRS-2.3.3** 重要查询必须建立索引以避免全表扫描：
- 实体按项目分桶查询。
- 分镜按剧集 + 项目联合查询。
- 关联表按主体 + 排序联合查询。
- 时间线片段按轨道查询。

### 2.4 全局数据库内容（系统数据）

**SRS-2.4.1** 全局数据库至少包含以下表：
- **渠道配置**：分类（LLM / TTI / ITV / TTS / 图床 / ...）、渠道定义 ID、加密后的 API Key、Provider 配置 JSON、模型清单 JSON、能力清单 JSON、来源（内置 / 插件）、所属插件 ID。
- **媒体默认值**：每个分类各保留一条"默认渠道 + 默认模型"。
- **应用键值偏好**：用户级 UI 状态与偏好（主题 ID、语言、最近打开项目 ID 等），值以 JSON 形式存储。
- **聊天会话 / 消息**：会话元信息、消息序列（seq、role、content、reasoning、extras）。
- **任务**：见第 4 章。

### 2.5 数据完整性与一致性

**SRS-2.5.1** 所有跨表写入必须封装在事务中。原子性失败示例：
- 创建项目：插入项目主表 + 创建默认时间线必须同时成功。
- 保存聊天：会话 UPSERT + 旧消息 DELETE + 新消息批量 INSERT 必须同时成功。
- 保存分镜：主表 + 三类关联表 + 媒体绑定必须同时成功。

**SRS-2.5.2** 数据库写入失败必须以异常向上抛出；前端必须将异常呈现给用户，禁止吞错装作成功。

**SRS-2.5.3** 系统启动时必须执行一次 WAL checkpoint，应用关闭前再做一次截断式 checkpoint，避免 WAL 持续增长。

### 2.6 备份、导入、导出

**SRS-2.6.1** 系统必须支持"按项目导出"：
- 输出格式为单个 zip 包。
- 包含项目目录下全部业务数据（媒体文件、SQLite 序列化后的全量 JSON）。
- 默认排除缓存目录与临时目录。
- 导出过程使用流式归档，避免大项目耗尽内存。

**SRS-2.6.2** 系统必须支持"按项目导入"：
- 解压至临时目录，读取序列化 JSON。
- 以新项目 ID 重建：创建项目目录 → 创建项目 DB → 批量写入所有实体 → 批量复制媒体文件。
- 导入过程中若任何环节失败，需清理临时目录与已创建的目标目录，避免半态项目残留。

**SRS-2.6.3** 导入时若 JSON 中存储的是相对路径，需重映射到新项目下的对应资产目录。

**SRS-2.6.4** 删除项目必须：
- 通过外键级联清空该项目所有数据库记录。
- 清空全局任务表中 scope 等于该项目的任务记录。
- 删除该项目在文件系统上的整个目录。
三步必须按顺序完成，任意一步失败必须留下可被用户识别的孤立状态记录。

## 3. 文件存储

### 3.1 目录布局

**SRS-3.1.1** 系统必须遵循固定的目录布局：

```
<业务根>/
├── settings.db                    # 全局数据库
├── logs/                          # 日志
├── ffmpeg/                        # FFmpeg 二进制（按平台 / 架构分目录）
├── ffmpeg-cache/                  # FFmpeg 任务的临时工作目录
├── plugins-runtime/               # 已安装插件的运行根
├── plugins-staging/               # 待安装插件包暂存
├── style-references/              # 全局风格参考图
├── voiceLibrary/                  # 全局音色库
│   ├── library.json
│   └── samples/
├── marketplace-cache/             # 插件市场下载缓存
├── updater-cache/                 # 应用更新包缓存
├── _userData/                     # Chromium 框架数据（Cookie/Cache/SingletonLock）
└── projects/                      # 项目根（受"运行时存储根"重定向控制）
    └── {projectId}/
        ├── koma.db                # 项目数据库
        ├── assets/
        │   ├── characters/{id}/
        │   ├── scenes/{id}/
        │   ├── props/{id}/
        │   └── shots/{id}/
        ├── cache/
        │   ├── thumbnails/
        │   ├── waveforms/
        │   └── previews/
        ├── episodes/{id}/
        ├── exports/
        └── temp/
```

**SRS-3.1.2** 业务根下的"固定服务目录"（logs / ffmpeg / plugins-runtime / style-references / voiceLibrary 等）不受运行时存储根重定向影响。只有 `projects/` 跟随用户选择的存储根。

**SRS-3.1.3** 业务根必须与 Electron Chromium 的 `userData` 物理隔离，避免用户清理浏览器缓存时误伤业务数据。

### 3.2 资产生命周期

**SRS-3.2.1** 所有大文件（图、视频、音频）必须存于文件系统；数据库只保存元数据 + 路径。禁止把媒体二进制写入 SQLite。

**SRS-3.2.2** 资产入库时必须收集以下元数据并落库：MIME、宽 / 高、时长（ms）、帧率、字节数、内容指纹、来源标签。视频与音频必须同时生成缩略图或波形图。

**SRS-3.2.3** 资产指纹用于去重：当同一项目内尝试入库相同指纹的内容时，系统应复用既有资产记录而非重复落盘。

**SRS-3.2.4** 资产持有"引用计数"字段：被时间线片段、分镜版本等业务对象引用时增加；解除引用时减少。引用计数为 0 的资产可被"清理"动作回收。

**SRS-3.2.5** 缓存目录（缩略图 / 波形 / 预览）必须支持：
- 跟随主资产删除自动失效。
- 按时间戳过期回收（缩略图 7 天等可配置策略）。
- 按总大小 LRU 回收（波形目录上限 1 GB 等可配置策略）。

### 3.3 上传 / 下载 / 流式 I/O

**SRS-3.3.1** 用户从浏览器选择文件上传时，必须经主进程文件控制器写入项目资产目录，禁止依赖渲染端 Blob 长持有。

**SRS-3.3.2** 远端资源下载必须：
- 支持 `data:` URI 与 http(s) 两种来源。
- 优先使用 Electron 网络栈（享受证书与代理设置）。
- 对某些已知响应头不兼容的 CDN（如部分对象存储），自动降级到 Node http 模块。
- 全程流式 pipe 到磁盘，避免把大文件加载进内存。
- 单次下载超时 10 分钟、最多 5 次重定向。
- 根据响应 Content-Type 修正本地文件扩展名。

**SRS-3.3.3** 文件控制器对外暴露的 API 必须强制路径白名单（同 1.4 协议白名单），禁止前端通过参数访问任意路径。

### 3.4 FFmpeg 媒体处理

**SRS-3.4.1** 系统内置 FFmpeg 二进制并支持多平台多架构：构建产物包含 macOS x64 / arm64、Windows x64、Linux x64。macOS arm64 缺失时允许回退到 x64 由 Rosetta 翻译。

**SRS-3.4.2** FFmpeg 调度必须遵循单实例 + FIFO 队列模型，原因是大量并发 spawn 会撑爆系统资源：
- 全局只有一个执行中进程。
- 任务串行执行，按提交顺序。
- 任务必须支持取消（kill 进程 + 清理工作目录）。
- 长任务必须支持进度回调（解析 FFmpeg stderr 中的时间戳与目标时长比例）。

**SRS-3.4.3** FFmpeg 必须提供至少下列高层操作：
- 媒体信息读取（时长 / 宽高 / 帧率 / 音视频轨存在性）。
- 抽帧（指定 FPS / 起止时间 / 输出宽度 / 质量）。
- 宫格图分割（2×2 / 3×3 / 4×4 / 5×5）。
- 图像放大（×2 / ×4）与中心裁剪（指定比例与锚点偏移）。
- 音频波形 PNG 生成。
- 音视频分离。
- 帧序列 + 多音轨合成视频（指定 FPS / 分辨率 / 码率）。
- 视频/图片/音频混合 clip 拼接。
- 视频快速裁剪（优先 stream copy）。
- 视频放大（×2 / ×4）。

**SRS-3.4.4** FFmpeg 任务必须把临时文件落在专用缓存目录的"任务子目录"内，任务结束后无论成功失败都必须递归清理。

### 3.5 全局媒体资源（非项目内）

**SRS-3.5.1** 系统必须支持"全局风格参考图"：用户对每个内置预设可上传自定义封面，覆盖默认图，按预设 ID 独立管理。读取时若用户覆盖图存在则优先返回，否则回退到内置图，并附带文件最后修改时间用于缓存破坏。

**SRS-3.5.2** 系统必须支持"全局音色库"：
- 一个 JSON 清单文件记录所有音色元数据（含来源、性别、语种、标签等）。
- 单独的 samples 目录存放音色样本音频（按分类组织）。
- 上传样本以 base64 入参，落地为 wav/mp3，并把相对路径写入清单。

**SRS-3.5.3** 系统必须支持"项目级风格参考图"：每个项目可独立设置一张主视觉风格图，落在项目 assets 目录下。

## 4. 后台任务系统

### 4.1 设计目标与范围

**SRS-4.1.1** 后台任务系统是 Koma 唯一的"异步执行枢纽"，必须承担：
- 生成类（文生图 / 图生视频 / TTS / LLM 推理）。
- 处理类（FFmpeg 转码 / 缩略图）。
- 分析类（剧本分析 / 分镜分析）。
- 同步类（资产下载 / 上传）。
不允许在业务代码中存在脱离任务系统的"裸 setInterval 轮询"或"裸 Promise"长任务。

### 4.2 任务模型

**SRS-4.2.1** 任务记录必须包含以下字段：
- 唯一 ID、scope（`global` / `project:<id>` / `chat:<sessionId>`）。
- type（业务类型，如 `tti` / `itv` / `tts` / `shot-analysis` / `script-analysis`）。
- target_kind + target_id（任务作用对象，如分镜 / 角色 / 集数 / 灵绘节点）。
- status：`pending` / `running` / `completed` / `failed` / `cancelled`。
- progress：0..100。
- remote_task_id：对应到第三方 API 的任务 ID，用于轮询/恢复。
- attempt、max_retries、error。
- payload（完整业务对象，JSON）。
- created_at、updated_at、heartbeat_at、completed_at。

**SRS-4.2.2** 任务持久化到全局数据库的 `tasks` 表，并按 (scope)、(scope, status)、(scope, target_kind, target_id)、(status, completed_at) 建索引。

### 4.3 调度模型

**SRS-4.3.1** 任务按 type 分队列，每个 type 独立 FIFO + 独立并发上限。缺省并发上限示例：
- 文生图：6
- 图生视频：4
- TTS：8
- 分镜分析 / 剧本分析：1（受 LLM 池限制）
- 默认全局：4

**SRS-4.3.2** 每个 type 通过注册一个 handler 提供执行逻辑。Handler 必须接收以下上下文：
- 任务 ID。
- 业务入参。
- Abort 信号（用户取消时触发）。
- 进度上报回调（受节流控制，详见 4.4）。
- 状态补丁回调（用于在执行过程中更新 payload 与 remote_task_id）。

**SRS-4.3.3** Handler 实现可以选择两种执行域：
- 主进程内执行（CPU / 文件 / 数据库 / FFmpeg）。
- 委托给渲染进程执行（需要 LLM SDK、Provider 客户端等渲染端能力）。委托通过 1.3.4 描述的反向调用通路完成。

**SRS-4.3.4** 任务提交、取消、查询、删除、垃圾回收必须以 IPC 方法暴露给渲染端，渲染端通过统一的 store 订阅任务变化。

### 4.4 进度与广播

**SRS-4.4.1** 进度更新必须节流：
- 最小时间间隔 200 ms。
- 最小变化幅度 1%。
- 强制 flush 用于状态切换（任务完成、失败、取消）。

**SRS-4.4.2** 任意任务状态变化必须广播到所有渲染端，前端通过一个"任务 store"接收增量更新，保证多窗口看到一致视图。

**SRS-4.4.3** 前端 store 必须实现版本防回退：在收到广播时比较 `updated_at`，旧版本不允许覆盖新版本。

### 4.5 取消与重试

**SRS-4.5.1** 取消语义：
- 任务在排队中：直接从队列移除并标记为 `cancelled`。
- 任务在执行中：触发 Abort 信号，handler 必须及时检查信号并尽快退出，主进程协调清理（kill FFmpeg 子进程、停止轮询循环等）。
- 取消必须广播状态变化给所有渲染端。

**SRS-4.5.2** 系统支持每个任务一个 `max_retries` 上限。瞬时错误（HTTP 408 / 429 / 5xx / Gateway / ECONN / ETIMEDOUT / ENOTFOUND / "timeout" 等）允许自动重试；持久错误（业务参数错误 / 内容审核拒绝 / 凭证错误）必须直接进入 `failed`。

**SRS-4.5.3** 远程轮询型任务（如媒体生成）必须：
- 每 5 秒查询一次远端状态。
- 总轮询时长不超过 30 分钟。
- 单次快照请求失败不立即终结任务，遵循 4.5.2 的瞬时错误判定。

### 4.6 启动恢复与垃圾回收

**SRS-4.6.1** 应用启动时必须对未完成任务（`pending` / `running`）进行复核：
- payload 标记为 `recoverable` 且存在 remote_task_id 的任务（典型为远程轮询）：状态回置为 `pending` 等待重新入队。
- 其他不可恢复任务：标记为 `failed`，错误信息为"任务在软件重启后中断"。

**SRS-4.6.2** 系统必须支持垃圾回收：
- 已进入终态的任务按"保留天数"过期清理（缺省 7 天）。
- 每个 scope 下的终态任务数量受上限约束（缺省 200 条），超出按时间剪枝。
- 保留策略以 KV 偏好的形式可配置。

**SRS-4.6.3** 删除项目时必须同步清理该项目 scope 下的所有任务记录，避免成为孤儿。删除单个分镜 / 角色等实体时，同步清理对应 target 的任务。

### 4.7 任务与业务的对接示例（规范）

**SRS-4.7.1** 生成类任务（媒体）的标准流程：
1. 业务调用提交任务，立即返回任务 ID，UI 切到"生成中"。
2. Handler 调用 Provider 创建远程任务，得到 remote_task_id，写入 payload。
3. 轮询循环 → 进度回调 → store 广播。
4. 远程完成后：handler 下载产物 → 入库为资产 → 绑定到业务对象（分镜版本 / 节点输出）。
5. 终态广播；UI 显示成品。

**SRS-4.7.2** 分析类任务（LLM）：必须通过委托给渲染端 handler 执行；任务级超时 30 分钟；并发限制为 1。

## 5. 插件系统

### 5.1 设计目标

**SRS-5.1.1** 插件系统服务于三个目标：
1. 将"第三方供应商接入"从主仓库剥离出去（Provider 类插件）。
2. 允许有限度的功能扩展（UI 入口、工具命令、AI 代理、外部协议网关）。
3. 提供受控的执行沙箱，避免插件污染主仓代码或越权访问用户数据。

### 5.2 插件包结构与清单

**SRS-5.2.1** 每个插件以一个 zip 包发布，解压后必须至少包含：
- `manifest.json`：元数据清单。
- `entry` 字段指向的入口文件（后端、前端或两者）。
- 可选 `dist/`、`README.md`、`assets/`。
不允许包含 `node_modules`。安装时白名单过滤目录，拒绝异常文件。

**SRS-5.2.2** Manifest 必填字段：
- 唯一 ID（反向域名）、显示名、版本号（SemVer）。
- 类别（provider / global / mcp / tool / agent）。
- 兼容性声明 engine：`minAppVersion` / `maxAppVersion`（可选）/ `sdkVersion`。
- 申请的能力 scope 列表（见 5.4）。
- 入口：`entry.backend` 和/或 `entry.frontend`。
- 按类别补充的子字段（providerMeta / globalMeta / mcpMeta / toolMeta / agentMeta）。

### 5.3 插件类别

**SRS-5.3.1** **Provider** —— 第三方模型 / 服务接入：
- 必须声明渠道分类（LLM / TTI / ITV / TTS / 图床等）与能力集合。
- 必须实现 `createProvider(config, ctx) → ProviderInstance`，由系统按需实例化。
- 凭证存储与解密通过统一的渠道配置服务（见 6 章），插件不允许私自存放 API Key。

**SRS-5.3.2** **Global** —— 全应用 UI 扩展：
- 注册一条主路由 + 侧栏导航项（icon / label / order）。
- 前端入口以 lazy import 加载，失败时不能影响主壳。
- 不允许向其他业务区域（如分镜编辑器、灵绘画布）注入自定义 UI（受当前扩展点边界限制）。

**SRS-5.3.3** **MCP** —— Model Context Protocol 服务器：
- 支持四种 transport：stdio、SSE、WebSocket、internal。
- 必须列出提供的 tools 与 resources，由系统统一注册到 capability registry，供 chat / agent 调用。

**SRS-5.3.4** **Tool** —— 快捷工具：
- 注册一条菜单项（label / icon / 快捷键）。
- 点击触发由插件定义的命令，可调用 capability registry 中的任何能力。

**SRS-5.3.5** **Agent** —— AI Worker 代理：
- 声明能力集合、工具集合、系统提示词、温度、最大 token 等。
- 必须实现 `createAgent() → WorkerAgentDefinition`。

### 5.4 能力权限（Scopes）

**SRS-5.4.1** 系统识别有限的能力 scope，插件必须在 manifest 中显式申请。当前白名单：

| Scope | 含义 |
|---|---|
| `settings:read` / `settings:write` | 读 / 写应用偏好 |
| `projects:read` / `projects:write` | 读 / 写项目数据 |
| `prompts:override` | 覆盖系统提示词 |
| `storage:limited` | 在插件沙箱目录内的文件读写 |
| `network:external` | 发起外部 HTTP 请求 |
| `mcp:server` / `mcp:tool` / `mcp:resource` | 注册 MCP 服务器 / 工具 / 资源 |
| `agent:register` | 注册 Agent worker |
| `spawn:process` | 启动子进程 |

**SRS-5.4.2** 激活时校验申请的 scope 全部在白名单内；运行时每次调用 API 二次校验当次操作所需 scope 是否在已授权集合中。

### 5.5 插件运行时

**SRS-5.5.1** 插件以独立模块在主进程加载，提供以下生命周期钩子：
- `onActivate(api)`：激活时调用，可注册 Provider / MCP / Agent。
- `onDeactivate()`：停用时调用，必须释放所有注册项。

**SRS-5.5.2** 插件不允许直接 `require` 主仓内部模块，只能通过传入的 API 对象访问能力。API 表面至少包含：

| 模块 | 能力 |
|---|---|
| `core` | 获取版本 / 插件目录 / 数据目录 |
| `fs` | 沙箱内 readFile / writeFile / deleteFile / exists / listDir |
| `net` | 受控 fetch（自动遵守 1.5 节安全策略） |
| `spawn` | 启动子进程（仅在持有 `spawn:process` 时） |
| `channels` | 注册 Provider / 维护 Provider 配置 / 查询 Provider |
| `mcp` | 注册 / 注销 MCP server、tool、resource |
| `agents` | 注册 / 注销 / 列出 Agent worker |
| `capability` | 查询、解析、调用任意已注册能力 |
| `log` | debug / info / warn / error（自动以 `[Plugin:<id>]` 前缀输出） |
| `activation` | 读取激活信息与许可证 |

**SRS-5.5.3** 插件数据目录隔离：每个插件分配独立的 `data/` 子目录，所有 `fs.*` 调用必须解析到该目录内（resolve → 规范化 → 前缀校验），越界一律拒绝。

**SRS-5.5.4** 插件加载失败时主应用必须正常运行，并在"插件管理"页面显示失败原因。

### 5.6 插件兼容性

**SRS-5.6.1** 加载前校验：
- 应用版本必须落在插件 `engine.minAppVersion ≤ X ≤ engine.maxAppVersion` 区间。
- 插件 SDK 主版本必须与系统 SDK 主版本相同，且次版本 ≤ 系统 SDK 次版本。
- 申请的 scope 全部在已知白名单内。
任一项不通过：状态记为 `incompatible` 并给出可读原因。

### 5.7 安装、激活、停用、卸载

**SRS-5.7.1** 安装流程：
1. 接收 zip 包 → 解压到 staging。
2. 校验 manifest 与目录白名单。
3. 复制到 `plugins-runtime/<id>/`，建立 `data/` 子目录。
4. 写入插件注册表（持久化的"已安装清单"）。

**SRS-5.7.2** 激活流程：
1. 兼容性校验通过。
2. 加载入口模块，调用 `onActivate(api)`。
3. 按类别处理注册：Provider 工厂入注册表、MCP 服务器拉起、Agent 工厂入 worker 池。
4. 状态置为 `active`。

**SRS-5.7.3** 停用：调用 `onDeactivate()` → 清空插件注册的所有 Provider / MCP / Agent → 状态置为 `loaded`。

**SRS-5.7.4** 卸载：先确保停用 → 删除 `plugins-runtime/<id>/` 整个目录（含 `data/`）→ 从注册表移除。

### 5.8 内置插件

**SRS-5.8.1** 系统支持"内置插件"概念：作为打包资源随应用一起发布，每次启动自动同步至 `plugins-runtime/`。同步策略：
- 覆盖二进制文件确保最新。
- 保留用户写入到该插件 `data/` 目录内的内容。
- Provider 配置通过统一渠道配置服务管理，不被覆盖。

**SRS-5.8.2** 内置插件必须由构建脚本统一编译；脚本支持：
- 按源 / 清单的最近修改时间增量构建（默认）。
- 强制重建（命令行参数）。
- 复制时排除 `node_modules`。

### 5.9 插件市场

**SRS-5.9.1** 系统必须接入一个远程"插件注册表"：
- 单一来源（受控 URL），返回插件目录与元数据。
- 使用 HTTP ETag 缓存（304 时复用本地）。
- 整个 registry 文件经 ed25519 签名验证（同应用更新签名体系）。
- 拉取超时 30 秒。

**SRS-5.9.2** 注册表中的每条插件记录包含：ID、名称、最新版本、下载 URL、SHA512、engine 约束。下载后必须校验 SHA512 才允许进入安装流程。

**SRS-5.9.3** 市场服务必须对同一插件的 install / update / uninstall 操作建立互斥锁，避免并发竞争产生半态。

**SRS-5.9.4** 市场服务必须在列表查询时执行"预兼容性校验"，对每条记录标注可安装 / 不兼容（含原因），UI 据此禁用按钮。

---

## 6. 系统数据管理（全局数据）

### 6.1 渠道凭证

**SRS-6.1.1** 系统对所有 LLM / TTI / ITV / TTS / 图床等外部能力以"渠道"为最小单元集中管理。一条渠道记录包括：分类、渠道定义 ID、显示名、加密后的 API Key、Provider 配置（非敏感字段）、模型清单、能力清单、来源（内置 / 插件 / 用户）、所属插件 ID、默认模型 ID、排序权重。

**SRS-6.1.2** API Key 必须使用操作系统的安全凭证存储能力加密后落盘：
- macOS：Keychain。
- Windows：DPAPI。
- Linux：libsecret（缺失时降级为受口令保护的本地加密文件）。

**SRS-6.1.3** Key 的"明文出口"只有一处：执行端（生成服务、网络代理）通过受控接口取明文，立即用于请求构造，禁止落入日志、IPC payload、前端 store。

**SRS-6.1.4** 渠道 DTO 回前端的字段不包含明文 API Key，仅包含 `hasApiKey: boolean` 用于 UI 判断。

**SRS-6.1.5** 渠道支持的操作：
- 列表（按分类与排序权重）。
- 创建 / 更新（含可选 Key 重置）。
- 删除。
- 批量导入（从插件初始化）。
- 与插件激活状态对账（reconcileActivation）。
- 设置 / 查询 / 取消"每分类默认值"。

### 6.2 媒体默认值

**SRS-6.2.1** 系统必须能为每个媒体分类（LLM / TTI / ITV / TTS）记录"默认渠道 + 默认模型"。业务在未指定具体渠道时，默认调用该记录。

**SRS-6.2.2** 默认值表使用 `category` 作为唯一键，UPSERT 语义。

### 6.3 应用键值偏好

**SRS-6.3.1** 系统必须提供一个键值表用于存储用户级偏好与 UI 状态。值字段以 JSON 形式存储任意结构。

**SRS-6.3.2** 缓存类典型用途：最近打开项目 ID、主题 ID、语言、任务保留策略（天数 + scope 上限）、上次窗口尺寸、运行时存储根、设置页折叠状态等。

**SRS-6.3.3** 提供 IPC 接口：get / set / delete。前端通过统一封装的"应用偏好客户端"读写，避免散落的 IPC 调用。

### 6.4 聊天历史

**SRS-6.4.1** 系统提供完整的对话持久化，包含两张表：
- 会话：ID、标题、创建时间、更新时间、消息数。
- 消息：会话 ID 外键、序号（seq）、role（user / assistant / tool / system）、content（JSON）、reasoning（思维链）、extras（工具调用 / 引用 / 附件等）。

**SRS-6.4.2** 保存会话必须原子化：会话 UPSERT + 旧消息全删 + 新消息批量插入 在同一事务内执行。

**SRS-6.4.3** 会话与消息按 (session_id, seq) 建索引，按更新时间倒序列出。

### 6.5 跨域数据查询规则

**SRS-6.5.1** 项目级与全局级数据互相不可越界：
- 项目 DB 不存任何全局共享数据。
- 全局 DB 不存任何项目 ID 强相关数据，唯一例外是任务表 `scope = project:<id>`。
- 切换项目时关闭旧项目 DB 连接、打开新项目 DB；同一时刻只持有一个项目 DB 连接。

**SRS-6.5.2** "最近打开项目"、"运行时存储根"等跨项目持久化必须放在全局 DB 或键值偏好表中，禁止依赖项目内部数据。

## 7. 主题系统

### 7.1 设计目标

**SRS-7.1.1** 主题系统必须把"视觉语言"集中表达为一组语义化设计 token，所有 UI 组件通过 token（而非硬编码颜色）取值。token 同时驱动：
- Ant Design 6 的 ConfigProvider。
- Tailwind CSS 工具类。
- 业务组件的内联样式或 CSS Modules（通过 CSS 变量）。

**SRS-7.1.2** 同一主题切换必须无需刷新 / 重启，并在所有打开的窗口同步生效。

### 7.2 语义 Token 维度

**SRS-7.2.1** 主题至少包含以下维度：

| 维度 | 子级 | 用途 |
|---|---|---|
| `bg` | app / surface / elevated / card / hover | 背景层级 |
| `border` | base / subtle / focus | 边框层级 |
| `text` | primary / secondary / tertiary / muted | 文字层级 |
| `accent` | base / hover / glow / onAccent | 品牌主色 |
| `status` | success / info / warning / error / onStatus | 状态色 |
| `radius` | sm / base / lg | 圆角层级 |
| `shadow` | sm / md / lg / glow | 阴影层级 |
| `space` | xs / sm / md / lg / xl | 间距尺度 |
| `z` | base / modal / dropdown / tooltip | 层级 |
| `overlay` | onBg | 半透遮罩 |

**SRS-7.2.2** Token 体系不允许出现"主题局部专属"的零散字段，所有新增 token 必须同时在所有主题中提供取值。

### 7.3 主题集合

**SRS-7.3.1** 系统至少内置以下主题：
- 深色主色 A（默认）。
- 深色主色 B。
- 浅色商务。
- 高对比度（无障碍）。

**SRS-7.3.2** 主题以独立模块声明并通过模块系统动态发现（增加主题不需要修改主题注册中心），但**必须满足类型与必填 token 完整性**。

### 7.4 与 Ant Design 集成

**SRS-7.4.1** 主题必须能编译为 Ant Design 6 的 ConfigProvider token：
- 全局 token：`colorPrimary` / `colorBgContainer` / `colorBorder` / `colorText` / 状态色等。
- 至少覆盖 40+ 组件的局部 token（Card、Modal、Button、Input、Slider、Radio、Switch、Table、Menu 等），与语义 token 一一映射。

**SRS-7.4.2** 必须刻意保留少数 Ant Design token 不被覆盖以保证组件行为一致：
- `colorTextLightSolid`（Tooltip 内白字）。
- `colorBgSpotlight`（Tooltip 反向高对比背景）。
"主色按钮上的文字色"通过 `accent.onAccent` + 自定义 CSS 变量解决，禁止污染上述全局 token。

### 7.5 与 Tailwind / CSS 集成

**SRS-7.5.1** 主题在挂载时必须把全部 token 注入到 `:root` 的 CSS 自定义属性（命名形如 `--token-bg-app`）。

**SRS-7.5.2** Tailwind 通过 `@theme` 把 `--color-bg-app` / `--color-accent` / `--color-on-accent` / `--radius-*` / `--space-*` 等映射为工具类（`bg-bg-app`、`text-on-accent` 等）。

**SRS-7.5.3** 业务组件使用 `var(--token-...)` 而不是硬编码颜色；这一条作为代码评审硬性要求。

### 7.6 首屏防闪烁

**SRS-7.6.1** 全局样式表必须内置一份"默认主题快照"的 `:root` 变量定义，作为首屏渲染兜底。运行时一旦解析出实际主题，立即覆盖。

**SRS-7.6.2** HTML 根元素必须挂上 `data-theme` 与 `data-themeMode` 属性，供 CSS 做主题特化样式（如某些边框只在浅色主题加深）。

### 7.7 主题切换与持久化

**SRS-7.7.1** 主题 ID 必须持久化到全局键值偏好表（key 形如 `ui.themeId`）。

**SRS-7.7.2** 启动顺序解析当前主题：
1. 从全局偏好读取。
2. 若未设置或失效，回退到默认主题。
3. 解析失败则使用代码内 DEFAULT。

**SRS-7.7.3** 用户切换主题：内存 state 更新 → 写入持久化 → 注入 CSS 变量 → ConfigProvider 重新计算。

### 7.8 无障碍

**SRS-7.8.1** 高对比度主题必须保证主色与状态色背景上的前景文字达到 WCAG AA 对比度。

**SRS-7.8.2** 焦点态必须有可见的边框或光晕（`border.focus` / `shadow.glow`），不能仅以颜色变化作为唯一指示。

### 7.9 当前边界（明确不在范围内）

**SRS-7.9.1** 当前阶段不支持以下能力（如需要请走单独立项）：
- 插件定义新主题。
- 用户在 UI 上自定义任意 token。
- 部分 token 的局部 hook 覆盖（仅支持"整套主题切换"）。

## 8. 跨子系统约束（横切关注点）

### 8.1 错误处理

**SRS-8.1.1** 所有 IPC 方法必须返回结构化结果：成功携带数据，失败抛出可序列化的错误对象（含 code / message / 可选 details）。前端必须将错误统一收敛到 toast / 错误页，禁止吞错。

**SRS-8.1.2** 主进程不允许出现未捕获的 Promise rejection；必须有顶层 handler 记录到错误日志并通知用户。

### 8.2 内部观测

**SRS-8.2.1** 每个子系统必须暴露最小诊断指标：
- 存储：项目数量、项目 DB 大小、全局 DB 大小、WAL 大小。
- 文件：业务根总占用、缓存目录占用、孤立资产数。
- 任务：各 type 的排队 / 运行 / 完成 / 失败计数。
- 插件：已安装数、已激活数、加载失败数。
- 网络：累计调用数、失败率（按渠道）。
诊断指标供"设置 / 诊断"页展示。

### 8.3 资源回收

**SRS-8.3.1** 系统必须提供"一键清理"动作，至少支持：
- 清理过期日志。
- 清理过期 / 超量任务记录。
- 清理项目缓存（缩略图 / 波形 / 预览）。
- 清理孤立资产（ref_count = 0 且超过宽限期）。
- 清理 FFmpeg 残留临时目录。
- 清理插件市场下载缓存与应用更新缓存。

### 8.4 时区与时间戳

**SRS-8.4.1** 所有持久化时间统一为 UTC 毫秒整数；前端展示时按用户时区格式化。禁止以本地化字符串形式入库。

### 8.5 国际化与文本

**SRS-8.5.1** 子系统对外暴露的错误码 / 状态枚举使用 ASCII 标识符；用户可见文本走 i18n 资源，不允许在主进程拼接中文字符串。

## 9. 验收要点

每个子系统在重构完成后必须通过以下基本验收：

- **底层规划**：单实例、IPC 白名单 CI 通过、CSP 不放宽、SSRF 测试覆盖、自定义协议路径越界用例全部拒绝。
- **持久化存储**：项目级 / 全局级数据完全隔离；版本迁移在空库与历史库上都能跑通；删项目后无残留记录、无残留任务、无残留目录。
- **文件存储**：上传 / 下载 / 转码全链路无内存爆涨；缓存目录有自动回收；FFmpeg 队列在并发 50 个请求时仍稳定。
- **后台任务**：进程重启后远端任务能恢复继续；取消能在 1 秒内停止 FFmpeg；进度广播延迟 ≤ 250 ms；GC 按策略生效。
- **插件系统**：插件加载失败不影响主壳；权限越界全部被拦截；内置插件构建增量生效；市场 ed25519 验签失败的包不可安装。
- **系统数据管理**：API Key 在数据库文件中以密文存储；前端无法以任何方式取到明文；切换项目后全局数据保持不变。
- **主题系统**：四套主题切换无残留样式；首屏无白闪；Tailwind / Antd / 业务 CSS 三处取值一致。
