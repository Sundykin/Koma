# 剧本到分镜一体化迭代路线图

## 1. 产品目标

把“剧本生成 → 角色/场景/道具提取 → 资产确认与生成 → 分镜生成与调整”收敛为一个持续可编辑的制作台，减少节点、抽屉和弹窗之间的往返，同时保留灵绘画布的自由组合能力。

北极星指标：从输入剧情大纲到获得第一组可用分镜图的中位耗时。

辅助指标：

- 完成一次剧本到分镜流程所需点击数。
- 首次生成前离开制作台的次数。
- 单个资产或镜头重生成时，被连带重生成的无关对象数量。
- 角色、场景和道具在后续镜头中的参考图复用率。
- 生成失败后的恢复率，以及用户找到重试入口所需时间。

## 2. P0 已落地基线

- 剧本、资产、分镜三阶段被合并到同一个 script/storyboard 节点制作台。
- LLM 结构化输出保留 `characters`、`scenes`、`props`，并归并为本地可编辑资产。
- 资产支持添加、编辑、删除、确认、重新提取和批量生成参考图。
- 已确认资产复用现有图片生成队列、provider、历史、失败重试和图片节点链路。
- 分镜图片节点记录来源资产 ID、类型和名称，便于后续回写与追踪。
- 成功生成结构化剧本后，在尚无资产时自动进入资产阶段。
- 内置“剧本到分镜一体化制作台”Recipe，可从工作流抽屉一次创建。
- 画布节点提供明确的“制作台”入口；保存/重载时按 RF 节点类型归一化业务类型。
- 制作台在节点上下空间不足时自动调整位置，并在有限高度内滚动。

## 3. 竞品对标结论

| 产品 | 可迁移模式 | Koma 对应方向 |
|---|---|---|
| LTX Studio | Script 起点与 Characters / Objects / Locations 统一 Elements 层 | 把剧本实体提升为可复用生产资产，而不是一次性提示词片段 |
| Boords | Script → Images → Review；角色一致性与局部帧修改 | 资产参考图锁定、单镜头局部修订、审核状态 |
| Storyboarder.ai | Script → Shot List → Storyboard → Consistency → Video → Animatic | 把镜头清单、视觉一致性检查和视频阶段串成连续状态 |
| FinalBit / NolanAI | 从剧本 breakdown 生成可复用生产实体 | 增加实体来源、出现镜头、别名合并和变更影响分析 |
| LibTV | 画布内紧凑批量生成 | 保持节点附近完成高频操作，复杂调整再进入沉浸视图 |

对标原则：迁移成熟的工作流和状态语义，不照搬积分、账号、云端锁定等 Koma 尚未具备的商业系统。

## 4. P1：从“可用”到“稳定生产”

### 4.1 项目级生产资产

- [x] 将节点内 `productionAssets` 同步到项目资产域，多个剧本或故事板节点可引用同一角色、场景和道具。
- [x] 资产库增加独立的媒体类型与 `角色 / 场景 / 道具 / 普通` 生产语义筛选，不再只按图片、视频、音频、文本区分。
- [ ] 支持资产别名合并、来源镜头回溯和重复候选提示（P8 进行中）。
- [x] 删除资产前显示被哪些镜头和节点引用，必须显式确认后才会破坏引用；镜头卡片同时保留缺失资产提示。

P1 实现说明：当前生产资产记录沿用工作区资产表，以 metadata 保存来源和生产语义；同一工作区、节点和生产资产使用稳定 ID 幂等写入。没有参考图的角色/场景/道具先以文本资产进入资产库，有参考图时再物化为图片资产。

### 4.2 锁定与局部重生成

- [x] 为生产资产增加 `draft / approved / locked` 状态，并兼容旧 `confirmed` 字段。
- [ ] 为镜头增加审核与锁定状态。
- 默认只重生成未锁定对象；批量操作必须明确展示作用范围。
- 镜头局部修改后，只标记受影响的下游图片、视频和合成节点为 stale。
- [x] 参考图生成成功后，可回写源生产资产；锁定后禁止隐式编辑和参考图版本变更。

### 4.3 一致性检查

- [x] 在分镜阶段集中检查镜头引用的角色、场景、道具资产是否缺失、未确认或缺少参考图。
- [x] 问题按资产聚合并列出受影响镜头；已有资产可直接跳回资产阶段定位，缺失资产可重新提取。
- [x] 将人物、场景、道具的引用关系展示在镜头卡片与表格中。
- [x] 进一步检查角色外观、服装、场景时段、关键道具状态和画面风格等语义约束冲突；仅凭明确证据提示，不阻断生成。

当前进展：制作台已具备生成前引用预检，镜头卡片/表格显示资产引用；删除引用资产会先列出影响范围，缺失、未确认和无参考图资产会在分镜阶段集中显示。问题行现在可将受影响镜头直接设为当前选择，底部生成入口只作用于这些镜头。P6 已补齐服装、场景时段、关键道具状态和风格冲突；P7 增加有意变化确认，确认指纹随镜头范围和证据变化自动失效。

### 4.4 失败与恢复

- 资产和分镜批量任务显示逐项状态、失败原因和单项重试。
- 离开或关闭制作台后保留阶段、选择、确认和失败状态。
- 增加“继续上次制作”入口，直接回到第一个未完成阶段。

## 5. P2：从“稳定生产”到“专业协作”

- [x] 资产参考图保留候选版本、当前版本与回退能力；旧 `referenceImage` 自动兼容为 V1。
- [ ] 镜头图补齐候选版本、当前版本与回退能力。
- 审核流：镜头支持批注、批准、驳回和锁定，批注可定位到具体字段或图像区域。
- Shot list：补齐景别、机位、运动、角色动作、对白、音效、时长和场景标签的批量编辑。
- Animatic：将批准后的分镜、对白/配音和时长直接组装为可预览动画样片。
- 变更影响分析：修改角色或场景资产时，先列出受影响镜头，再由用户选择刷新范围。
- 模板化生产规则：按漫剧、广告、MV、产品短片等类型保存镜头规模、节奏和一致性规则。

## 6. 每轮迭代方法

1. 从埋点或 Electron 实操回放中选择一个最大摩擦点。
2. 与一个明确竞品模式对照，写出“要迁移的语义”和“不迁移的系统依赖”。
3. 只做一个可以测量的闭环切片，并保持旧项目数据兼容。
4. 用状态/组件测试覆盖持久化与作用范围，再通过 Electron CDP 验证真实布局和交互。
5. 对比点击数、首帧耗时、离开制作台次数和无关重生成数量；未改善则回退或调整。

## 7. 下一轮建议

参考图候选版本、当前版本和回退能力已经落地，且继续复用现有项目资产同步和生成参考字段。下一轮先做资产别名合并与重复候选提示：同类资产仅在名称/别名或明确描述接近时提示，合并前展示来源镜头、参考图版本和锁定状态，确认后保留旧 ID 到 canonical ID 的可追溯映射。
