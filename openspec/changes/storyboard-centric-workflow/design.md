## Context

当前 Koma Studio 使用线性三步工作流（assets → storyboard → video），由 `EditorView.tsx` 中的 `editorStep` 状态机控制。用户必须按顺序完成资产提取后才能进入分镜，完成分镜后才能进入剪辑。

竞品分析（参考截图和 template/docs 文档）显示：成熟的漫剧/短剧工具都采用**分镜为中心**的布局——左侧场景/素材列表、中间大幅图片/视频预览区、右侧参数/提示词面板。工具功能通过弹出面板按需调用，而非强制线性流程。

template/resources/official_prompt_templates 中的 26 种提示词模板揭示了完整的创作管线：内容提取 → 剧本转换 → 提示词推理 → 批量处理 → 导出。这些能力应作为工具面板中的子流程暴露给用户。

## Goals / Non-Goals

**Goals:**
- 将分镜视图升级为主工作区，用户打开项目后直接进入分镜
- 提供右侧弹出工具面板，按需调用剧本导入、资产管理、推理、风格、导出等功能
- 放大分镜卡片中的图片/视频显示区域和提示词输入区域
- 让剪辑编辑器成为可选功能，分镜视图可直接导出
- 扩展提示词模板体系，覆盖竞品的多级模板能力

**Non-Goals:**
- 不删除现有的视频编辑器，只是降低其入口优先级
- 不重写底层数据模型（Shot、Episode、Project 结构保持不变）
- 不改变 AI Provider 抽象层
- 不实现实时协作功能
- 不迁移存储方案（SQLite 保持不变）

## Decisions

### Decision 1: 废弃三步导航，分镜视图作为项目主界面

**选择**: 打开 Episode 后直接进入分镜视图，原有的 assets/storyboard/video 步骤合并为一个统一工作区。

**替代方案**: 保留步骤但允许跳转——这会增加 UI 复杂度且不解决根本问题。

**理由**:
- 分镜是核心产出物，用户 80% 时间花在分镜视图
- 资产管理和剧本处理是辅助流程，按需弹出即可
- 竞品都采用这种模式，用户心智模型匹配

**实现**:
- `EditorView.tsx` 不再渲染步骤切换 UI，默认渲染 `StoryboardWorkspace`
- `EpisodeStepProgress` 类型简化或移除
- App.tsx 中 `view='editor'` 直接加载分镜工作区

### Decision 2: 分镜卡片布局重构——参考竞品两栏预览模式

**选择**: ShotCard 重构为大图预览 + 信息面板的两区布局：
```
┌──────────────────────────────────────────────────────────┐
│ [序号] [生成视频按钮] [批量数量]  [视频口型]  [风格]     │
│ ├── 左侧: 大幅图片/视频预览区 (占 40-50% 宽度)          │
│ │   └── 场景参考图列表（可选择）                         │
│ ├── 右侧上: 提示词输入区 (多行文本框, 充足高度)         │
│ ├── 右侧中: 角色/场景匹配标签                           │
│ └── 右侧下: 分镜文案/对话编辑区                         │
│ [编辑] [推理] [评论] [结构] [操作]  [覆盖分镜] [删除分镜]│
└──────────────────────────────────────────────────────────┘
```

**替代方案**: 保持当前 7 列表格布局——列太多，图片区域小，信息密度高但可读性差。

**理由**: 参考竞品截图，左侧大图+右侧参数是最佳实践，图片是核心产出需要最大展示空间。

### Decision 3: 右侧工具面板系统——Drawer 抽屉模式

**选择**: 使用 Ant Design Drawer 组件实现右侧弹出工具面板，每个工具面板是独立的功能模块。

**面板列表**:
1. **剧本工作室**: 导入文本/文件 → AI 拆分分镜 → 预览并确认
2. **资产管理**: 角色/场景/道具列表，支持提取、编辑、生成定妆照
3. **章节推理**: 批量提示词推理、章节改写、场景调整
4. **风格设置**: 从全局风格库选择/切换风格，实时预览
5. **导出中心**: 视频导出、剪映草稿导出、图片序列导出
6. **AI 助手**: 对话式 AI 辅助（已有功能迁移）

**替代方案**:
- Tab 切换——占用固定空间，不适合宽度有限的场景
- 独立页面——打断工作流，需要频繁跳转

**理由**: Drawer 不占用主区域空间，按需弹出，关闭后回到分镜视图，符合"工具"的心智模型。

### Decision 4: 分镜直出导出

**选择**: 在工具面板的"导出中心"和分镜视图工具栏都提供导出入口，直接从 Shot 数据生成输出，不需要经过时间线编辑器。

**导出模式**:
- **按分镜顺序导出视频**: 将所有 Shot 的视频/图片按顺序拼接，加入 TTS 音频
- **导出剪映草稿**: 直接从 Shot 数据构建剪映 draft_content.json
- **导出图片序列**: 按分镜顺序导出所有图片（支持超分辨率）

**实现**: 新建 `StoryboardExportService`，直接从 projectStore 的 shots 数据构建导出数据，复用现有 `JianyingExporter` 的模板逻辑。

### Decision 5: 提示词模板体系扩展

**选择**: 在现有 `promptTemplates.ts` 基础上，增加竞品模板体系中缺失的关键模板类别。

**新增模板类别**（参考 template/resources/official_prompt_templates）:
- 剧本转换模板（多种专业级别：基础/进阶/工作室级）
- 内容精炼模板（浓缩/扩写/润色）
- 章节划分模板（智能/均匀）
- 爆款开头模板
- 批量改写模板

**实现**: 扩展 `PromptTemplateType` 枚举，在 promptTemplates store 中注册新模板，工具面板中的各子流程引用对应模板。

### Decision 6: 风格面板集成

**选择**: 在工具面板中集成风格快速切换，从全局风格库中选择或自定义。

**实现**: 复用现有 `visual-style-management` 的 themePresets 机制，在工具面板中提供：
- 风格列表（带预览图）
- 一键应用到当前项目
- 自定义风格编辑入口

## Risks / Trade-offs

**[布局大改导致回归 Bug] → 逐步迁移**
分镜卡片布局重构影响面大。采用渐进式重构：先实现新布局组件 `StoryboardWorkspace`，保留旧组件作为 fallback，通过功能开关切换。

**[工具面板过多导致发现性差] → 分组 + 快捷键**
6 个工具面板可能让用户困惑。通过工具栏图标分组、快捷键绑定、以及上下文提示（如分镜为空时自动提示"导入剧本"）来提升发现性。

**[分镜直出质量不如编辑器] → 明确定位差异**
直出导出缺少转场、特效、精细调整。在 UI 上明确标注"快速导出"与"高级编辑"的区别，让用户根据需求选择。

**[提示词模板兼容性] → 模板版本化**
扩展模板可能与用户自定义模板冲突。新增模板使用独立 ID 空间，不覆盖用户已有自定义模板。

## Open Questions

1. 是否需要保留原有三步流程作为"新手引导模式"？
2. 工具面板是否支持同时打开多个（如同时查看资产和推理结果）？
3. 分镜卡片是否需要支持"紧凑模式"和"展开模式"切换？
