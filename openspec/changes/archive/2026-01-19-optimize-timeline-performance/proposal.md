# Proposal: optimize-timeline-performance

## Status
Draft

## Why

对比参考项目 `E:\Workspace\2025\代码备份\electron-egg` 的视频编辑器实现，Koma 的时间线编辑器存在严重的性能和功能差距：

### 性能问题

| 问题 | Koma 现状 | electron-egg 实现 | 影响 |
|------|-----------|-------------------|------|
| 拖拽响应 | 每次移动都重算吸附点 | 拖拽阈值检测(5px) + 延迟更新 | 拖拽卡顿 |
| 事件监听 | useEffect 重复绑定 | 单次绑定 + 正确清理 | 内存泄漏 |
| 组件重渲染 | memo 比较函数不完善 | 精细化 areEqual + 回调缓存 | 全量重渲染 |
| 播放引擎 | getDuration() O(n×m) 每帧计算 | 缓存时长值 | 播放帧率低 |
| 媒体加载 | 拖拽时频繁重加载缩略图 | 缓存 + 异步预加载 | 拖拽掉帧 |
| 时间同步 | 无容差直接同步 | 0.05s 容差避免频繁 seek | 播放抖动 |

### 功能差距

| 功能 | Koma 现状 | electron-egg 实现 |
|------|-----------|-------------------|
| DOM 查询 | CSS 选择器查询 | elementsFromPoint + data-* 属性 |
| 轨道高亮 | 无 | 拖拽时目标轨道/间隙高亮 |
| 时间控制 | 简单 RAF 循环 | MediaEngine 高精度时间控制 |
| 变换应用 | 固定顺序 | translate → rotate → scale 最优顺序 |
| 关键帧缓存 | 每次重新排序 | WeakMap 缓存已排序列表 |

## What Changes

### 阶段 1: 拖拽性能优化（高优先级）

1. **拖拽阈值检测** - 移动超过 5px 才开始真正拖拽
2. **事件监听器优化** - 正确绑定/清理，避免重复
3. **updateSnapPoints 依赖修复** - 移除 currentTime 依赖，按需更新
4. **RAF 节流统一** - 合并多个状态更新到单个 RAF

### 阶段 2: 组件渲染优化

1. **ClipItem memo 修复** - 完善比较函数，缓存回调
2. **TrackRow 优化** - 添加自定义比较函数
3. **回调函数缓存** - 使用 useCallback + 稳定依赖
4. **虚拟滚动** - 只渲染可见区域的片段（可选，大数据量时）

### 阶段 3: 播放引擎优化

1. **getDuration 缓存** - 轨道变化时才重算
2. **MediaEngine 重构** - 参考 electron-egg 的高精度时间引擎
3. **时间同步容差** - 添加 0.05s 容差避免频繁 seek
4. **关键帧插值缓存** - 缓存计算结果

### 阶段 4: 媒体加载优化

1. **FilmstripRenderer 缓存** - 避免重复加载相同帧
2. **预加载策略** - 异步加载媒体，加载完成触发渲染
3. **WaveformRenderer 优化** - 减少 Canvas 重绘

### 阶段 5: 功能补全

1. **elementsFromPoint 查询** - 使用 data-* 属性快速检测轨道
2. **轨道高亮反馈** - 拖拽时高亮目标轨道
3. **间隙拖放支持** - 支持拖拽到轨道间隙创建新轨道

## Affected Specs

- `timeline-editing`: 更新拖拽交互相关需求的性能指标
- `media-playback`: 添加播放性能相关需求

## Risks

1. **重构范围大** - 涉及多个核心组件，需要分阶段验证
2. **回归风险** - 可能影响现有功能，需要充分测试
3. **MediaEngine 重构** - 影响播放和渲染流程

## Alternatives Considered

1. **只修复关键问题** - 不够彻底，用户体验仍有差距
2. **完全采用 electron-egg 架构** - 工作量太大，与现有代码不兼容
3. **使用 Web Worker** - 过度工程化，当前数据量不需要

## Decision

采用渐进式优化方案：
- 分 5 个阶段实施，每阶段可独立验证
- 保留现有架构，借鉴 electron-egg 的优化策略
- 优先修复高影响问题（拖拽、播放）
- 可选优化（虚拟滚动）根据实际需求决定

## Success Metrics

- 拖拽操作保持 60fps（无明显掉帧）
- 播放时 CPU 占用降低 50%
- 内存泄漏归零
- 100 个片段场景下无性能下降
