## Context

当前灵绘视频节点虽然已经完成能力驱动改造，但交互层仍然保留了几类高噪音结构：

- `VideoNodeEditorPanels.tsx` 中存在大量常驻说明文字、提示段落和“导入输出/生成模式”双路径文案
- `VideoNodeEditor.tsx` 仍然把视频结果预览放在编辑框里，和节点卡片自身的缩略图表达重复
- `nodes/VideoNode.tsx` 当前主要显示静态封面，播放语义不完整，且节点点击与播放点击尚未彻底分离
- `useLinghuiCanvasMediaImport.ts` 导入到画布的视频只是给视频节点塞入 `source`，但 UI 层仍然把它放进“可切换到导入输出”的同一编辑器心智
- 比例、分辨率、时长虽然已有参数，但在视频编辑器里仍然容易被包裹在复杂说明中，识别成本高

用户给出的方向非常明确：

- 视频结果应直接在节点本身播放
- 播放按钮不能触发编辑框
- 编辑框删除结果预览
- 视频导入节点应是隐式的透传节点，而不是让用户在编辑框内切换模式
- 文案尽量删掉，必要解释用 Ant Design Tooltip
- 不考虑任何旧数据兼容

这意味着这次不是简单的视觉清理，而是要重新定义视频节点的职责边界：节点负责结果展示与播放，编辑框只负责生成配置，导入视频节点不再进入生成编辑心智。

## Goals / Non-Goals

**Goals:**

- 把视频生成结果预览从编辑框迁回节点卡片本身
- 让节点内播放按钮与“打开编辑器”彻底解耦
- 取消视频编辑框中的“导入输出”显式切换，改为来源驱动的隐式透传节点
- 将视频编辑框的长说明文案替换为 Tooltip 驱动的轻提示
- 将比例、分辨率、时长拆成三个独立且稳定的参数控件

**Non-Goals:**

- 不改写视频节点的执行编译协议和能力判定逻辑
- 不为旧工作区、旧视频节点或旧编辑态做兼容迁移
- 不在本次变更中扩展新的视频工具或新增渠道能力
- 不调整图片节点的既有规范，除非为对齐视频节点交互所必须

## Decisions

### Decision: 将视频节点分成“生成节点”和“透传节点”两种隐式交互变体

视频节点不再通过编辑框中的模式切换按钮在“生成视频 / 导入输出”之间来回跳转，而是根据节点是否持有本地 `source` 进入两种隐式变体：

- 生成节点：没有本地 `source`，承担提示词、能力和参数配置
- 透传节点：由画布导入视频直接创建，持有本地 `source`，只负责向下游输出既有视频

实现上仍可沿用现有 `linghui/video` 节点类型，但 UI 判定必须改为“来源驱动”，而不是“用户在编辑框里切换模式”。

Why:

- 用户不需要再理解“我现在是不是应该切到导入输出”
- 画布导入视频的行为与图片导入节点一致，心智更稳定
- 不用引入额外节点类型，也不必保留旧模式切换 UI

Alternatives considered:

- 保留模式切换但默认隐藏：仍然会把复杂度留在编辑器内部，不符合“直接就是透传节点”的目标
- 新增专门的导入视频节点类型：更干净，但会扩大节点类型面，当前没必要

### Decision: 节点卡片成为视频结果的唯一预览与播放载体

视频结果预览不再在编辑框里重复渲染，统一收口到 `nodes/VideoNode.tsx`：

- 结果存在时优先显示真实视频而不是纯静态 poster
- 节点卡片内提供显式播放按钮或覆盖控件
- 播放按钮的点击事件必须 `stopPropagation`，只控制播放，不打开编辑框
- 编辑框 MainSurface 删除“生成结果”区域

Why:

- 结果展示应该和节点本身绑定，符合“节点即产物”的画布语义
- 可以同时解决“编辑框过长”和“播放按钮误开编辑框”两个问题
- 节点层播放更接近图片节点的“卡片即结果”方向

Alternatives considered:

- 继续保留编辑框预览，仅额外补节点播放按钮：会造成双重预览和状态不一致
- 节点只显示 poster，播放仍放编辑框：无法满足用户要求

### Decision: 视频编辑框收缩为“必要参数面板 + Tooltip 解释”

`VideoNodeEditor.tsx` 和 `VideoNodeEditorPanels.tsx` 中的帮助文字、教程式段落和解释性卡片统一删除，仅保留：

- 上游输入摘要
- 提示词编辑器
- 能力切换器（如模型支持多能力）
- 渠道/模型选择
- 比例选择器
- 分辨率选择器
- 时长选择器

所有额外解释通过 Ant Design `Tooltip` 暴露在标题、图标或紧凑提示入口上。

Why:

- 视频编辑器真正高频的是“改输入、改 prompt、改参数、执行”
- 长文说明会挤压有效表单空间，也让节点轻编辑态失去“快调快跑”的效率
- Tooltip 能保留解释力，同时不让面板永久膨胀

Alternatives considered:

- 保留说明文案但折叠：仍然引入认知噪音，只是位置变化
- 全删不补 tooltip：会让部分能力/参数失去可发现性

### Decision: 参数布局固定为三个独立选择器

视频生成参数里的比例、分辨率、时长不再放进混合描述或复合面板里，而是固定为三个独立的选择控件。它们的排列优先保证稳定顺序和快速扫描，而不是穿插在说明文字里。

Why:

- 用户已经明确把这三项视为独立维度
- 独立控件更容易做能力约束、默认值和测试断言
- 与图片节点“比例/分辨率分离”的方向保持一致

### Decision: 视频工具面板继续悬浮，但说明文本退出主编辑区

视频工具如“高清 / 解析 / 合成”仍保留独立工具入口与悬浮面板，但不再在 MainSurface 内占用大段说明区：

- TopBar 负责工具入口
- Hover/聚焦弹出紧凑面板
- 工具用途通过 Tooltip 和简化标题表达

Why:

- 工具是次级能力，不该重新把主编辑区撑大
- 保持和图片工具面板的交互一致，减少额外学习成本

## Risks / Trade-offs

- [节点内直接播放视频会增加节点卡片的媒体状态复杂度] → 在节点组件内部局部管理播放状态，避免把播放状态提升到全局编辑器上下文
- [透传节点不再进入生成编辑态，可能让“替换视频”入口暂时缺失] → 本次先明确透传节点以直接下游复用为目标，不附带生成编辑能力；后续若需要替换入口，可作为独立变更追加
- [删除大段说明后，部分能力解释会不够显眼] → 为能力切换、工具入口和参数项统一补 Tooltip，保证信息可发现
- [不做旧数据兼容会让旧工作区继续保持旧交互痕迹] → 本次明确只服务未上线项目的新规范，实施中不为旧数据编写迁移逻辑

## Migration Plan

1. 先收缩视频编辑框结构，删除结果预览区和模式切换 UI
2. 再改造视频节点卡片，让结果在节点内联播放，并把播放按钮事件与打开编辑器解耦
3. 调整画布导入视频的节点创建逻辑，使其默认进入透传节点分支
4. 用 Tooltip 取代视频编辑器和工具面板中的说明性文本
5. 最后补齐测试，验证节点播放、编辑框裁剪和透传节点行为

本次不提供旧数据迁移，也不设计回滚兼容层；如果需要回退，只回退代码，不迁移存档。

## Open Questions

- 透传视频节点是否需要保留“替换本地视频”这一轻量操作入口；当前用户要求更接近“不可编辑直接给下游使用”，因此本次设计默认不把它纳入生成编辑框
