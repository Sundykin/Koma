# Design: 创作流程重构

## Context

当前系统中「AI智能拆解剧本」功能以弹窗向导形式呈现，与创作页面的步骤导航重复。用户期望：
- 创作流程遵循页面步骤导航，一步一步往下走
- 任务后台执行，不阻塞用户操作
- 页面跳转不丢失任务进度
- 每次进入创作页面能看到未完成任务的状态

## Goals / Non-Goals

### Goals
1. 统一创作流程，移除弹窗式向导
2. 实现后台任务系统，支持任务持久化和进度恢复
3. 修复资产数据持久化问题
4. 添加资产图片生成功能入口

### Non-Goals
- 不改变现有API调用逻辑
- 不重构底层存储结构
- 不添加任务队列优先级管理

## Decisions

### 1. 后台任务架构

**决策**：使用单例 `TaskManager` + 项目级 `tasks.json` 持久化

```
TaskManager (单例)
├── 内存任务列表 Map<taskId, Task>
├── 轮询器 (每3秒检查异步任务状态)
└── 持久化 (每次状态变更写入 tasks.json)

tasks.json 结构:
{
  "tasks": [
    {
      "id": "task-uuid",
      "type": "script-analysis" | "asset-generation" | "shot-render",
      "status": "pending" | "running" | "completed" | "failed",
      "progress": 0-100,
      "targetType": "episode" | "character" | "scene" | "prop" | "shot",
      "targetId": "xxx",
      "result": {...} | null,
      "error": string | null,
      "createdAt": timestamp,
      "updatedAt": timestamp
    }
  ]
}
```

**原因**：
- 简单直接，无需引入复杂的任务队列系统
- 项目级存储，跟随项目一起管理
- 便于调试和手动恢复

### 2. 创作步骤与任务的关系

**决策**：每个步骤显示相关任务的状态，不阻塞步骤切换

```
剧本步骤:
├── 显示剧本编辑器
├── 显示「AI解析」按钮
└── 如果有解析任务，显示进度条

资产步骤:
├── 显示角色/场景/道具列表
├── 每个资产卡片显示生成状态
└── 提供「生成定妆照」等按钮

分镜步骤:
├── 显示分镜列表
├── 每个分镜显示渲染状态
└── 提供「批量渲染」按钮
```

**原因**：
- 用户可以在任务执行时浏览其他内容
- 不强制等待任务完成
- 灵活的工作流程

### 3. 解析结果持久化时机

**决策**：解析任务完成后立即持久化

```
剧本解析完成后:
1. 保存角色列表到 characters.json
2. 保存场景列表到 scenes.json
3. 保存道具列表到 props.json
4. 保存分镜列表到 episodes/{id}/analysis.json
5. 更新任务状态为 completed
```

**原因**：
- 确保数据不丢失
- 便于后续步骤读取

### 4. UI 状态指示

**决策**：在步骤导航栏下方添加任务状态条

```
┌─────────────────────────────────────────┐
│ 剧本 → 资产 → 分镜 → 剪辑              │ <- 步骤导航
├─────────────────────────────────────────┤
│ 🔄 正在解析剧本... 45%  [████░░░░░░]   │ <- 任务状态条
└─────────────────────────────────────────┘
```

**原因**：
- 不遮挡主内容
- 始终可见当前任务状态
- 可展开查看详细任务列表

## Risks / Trade-offs

| 风险 | 缓解措施 |
|------|----------|
| 任务状态不同步 | 使用轮询 + 事件通知双重机制 |
| tasks.json 损坏 | 启动时验证，无效则重建 |
| 内存中任务过多 | 只保留最近7天的任务记录 |

## Migration Plan

1. 先实现 TaskManager 和持久化逻辑
2. 修改解析服务使用 TaskManager
3. 在资产步骤添加生成按钮
4. 最后移除 ScriptAnalysisWizard

## Open Questions

1. 是否需要支持任务取消？（暂不支持，API层面限制）
2. 失败任务的重试策略？（手动重试，不自动）
