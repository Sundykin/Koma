## Context

当前灵绘节点编辑器已经迁移到 React Flow，但轻编辑态仍然沿用“节点上方或下方单块浮层”的思路：

- `LinghuiNodeEditor.tsx` 只会在节点上方或下方放置一块宽卡片，节点本体可能被遮住
- `ImageNodeEditor.tsx` 无论当前是否处于生成模式，都会保留显著的大型上传区
- `VideoNodeEditor.tsx` 也会把上传区、提示词、参考摘要、工具预设和参数堆在同一面板里
- `LinghuiPromptEditor.tsx` 虽然功能完整，但放进节点弹窗后仍像“卡片里的第二张卡片”，和外层浮层视觉割裂
- 图像工具和视频工具通过大块 preset panel 直接插入主表单，导致节点编辑区不断变长

这些问题会直接影响画布操作效率：

- 当前节点被编辑时不可见，用户难以维持“画布上下文”
- 图片/视频节点没有根据 `generate/import` 场景裁剪内容，出现大量无效控件
- 工具能力和主配置混在一起，降低高频编辑效率

## Goals / Non-Goals

- Goals:
  - 让轻编辑态围绕节点展开，而不是挡住节点
  - 建立“上方工具条 + 节点主体 + 下方主编辑区”的空间关系
  - 按图片/视频节点当前模式裁剪内容，隐藏无关控件
  - 将图像工具和视频工具改为独立次级能力入口
  - 让提示词编辑器视觉上融入弹窗背景，减少割裂感
- Non-Goals:
  - 不在本次变更中改写节点执行引擎或引用编译逻辑
  - 不新增节点类型，也不改变现有图结构存储格式
  - 不把沉浸式编辑态完全移除，本次只重构轻编辑态和节点专属编辑内容

## Decisions

### Decision: 轻编辑态改为“围绕节点”的双区浮层

轻编辑态不再使用单块浮动卡片，而是拆成两个彼此关联的区域：

- 上方紧凑工具条：承载关闭、折叠、轻编辑/沉浸式切换、运行当前节点、模式切换或工具入口
- 下方主编辑面板：承载当前节点最核心的内容编辑区域
- 中间留出节点可视空隙：确保节点卡片本体在编辑过程中仍能看见

面板定位采用“优先上下包裹，边缘时左右避让”的策略：

1. 首选将工具条放在节点上方、主编辑面板放在节点下方
2. 若视口空间不足，则允许将下方面板偏移到左下或右下
3. 无论如何降级，都不能直接覆盖节点主体的主要可视区域

Why:

- 用户在编辑时仍能看到节点标题、状态和输入输出位置，画布语义不会断开
- 与现有 React Flow 节点交互更匹配，不需要完全推翻节点本体
- 比“只放一张大卡片”更接近用户提供的参考图心智

Alternatives considered:

- 继续优化单块浮层：实现简单，但仍难避免挡住节点
- 回退为内联节点表单：会显著增大节点体积，与当前紧凑画布方向冲突

### Decision: 图片节点按 `generate` / `import` 模式裁剪内容

图片节点的编辑内容按模式拆分，而不是一套表单兼容所有场景。

`generate` 模式下展示：

- 上游参考摘要
- 紧凑的“附加参考图”入口，而不是大面积上传区
- 提示词编辑器
- 生图渠道、比例、分辨率、宫格、批量等生成参数

`import` 模式下展示：

- 素材预览
- 上传图片 / 替换图片 / 清空素材
- 导入输出说明

`import` 模式下隐藏：

- 提示词编辑器
- 生图渠道和生成参数
- 宫格、批量等仅生成模式有意义的配置

Why:

- 生成图片时，主要来源应是上游参考和提示词，不应被大上传区打断
- 导入输出模式的核心是“提供可给下游复用的产物”，提示词并不参与当前节点执行
- 可以在不改变数据结构的前提下，明显降低节点弹窗噪音

### Decision: 视频节点按“生成 / 导入”场景拆分主编辑区

视频节点沿用相同思路：

生成视频时展示：

- 图片/视频/音频输入摘要
- 提示词编辑器
- 参考模式、渠道、比例、分辨率、时长等参数

导入视频时展示：

- 视频预览
- 上传视频 / 替换视频 / 清空素材
- 导入说明

导入模式隐藏：

- 提示词编辑器
- 参考模式
- 生成参数

Why:

- 当前上传区在视频节点里同样过于显眼，会把“多模态输入生成视频”的主路径打散
- 导入模式的目标是传递已有视频结果，不需要再编辑生成语义

### Decision: 图像工具和视频工具改为独立次级工具面板

多角度、扩图、打光、重绘、高清、解析、合成等工具不再作为“主编辑区里默认堆叠的大卡片”，而是改成独立的工具入口和次级面板。

交互原则：

- 工具入口优先放在上方工具条或紧凑工具轨中
- 激活工具后，在主编辑区之外打开次级工具面板
- 关闭工具时，主编辑区内容结构保持稳定，不因为工具开关而整体跳动
- 在导入模式下，如果某些工具只对生成模式有效，则工具入口应明确提示并引导切换，而不是混入主表单

Why:

- 工具能力属于“增强操作”，不应干扰节点的主路径配置
- 可以更接近“参考图 / 工具能力 / 核心参数”三条并行心智，而不是把所有内容塞进一列

### Decision: 提示词编辑器与节点弹窗共享同一视觉层

提示词编辑器保留现有 `@` 引用、补全和预览能力，但在节点弹窗里改为更融合的视觉层次：

- 与外层面板共享主背景色和圆角体系
- 减少单独边框、阴影和“卡片中再套卡片”的感觉
- 让编辑器区域像弹窗内容的一部分，而不是额外插入的组件盒子

Why:

- 当前提示词编辑器功能够用，但视觉上过度突出，与“融合到画布”目标相反
- 这是低风险高收益的 UI 改造，不需要重写引用系统

## Risks / Trade-offs

- 双区浮层的定位算法会比单块面板更复杂
  - Mitigation: 先定义固定的节点安全间距和最小工具条/面板尺寸，再做边缘降级
- 模式切换时如果直接卸载表单，可能让用户误以为数据丢失
  - Mitigation: 隐藏无关字段而不是清空它们；执行时只消费当前模式对应字段
- 工具面板独立后，状态管理会更分散
  - Mitigation: 明确区分“主编辑状态”和“次级工具状态”，并限制同一时间只打开一个工具面板

## Migration Plan

1. 先重构 `LinghuiNodeEditor` 的轻编辑态布局和定位规则
2. 再分别重构 `ImageNodeEditor` 与 `VideoNodeEditor` 的主编辑区分段
3. 最后调整 `LinghuiPromptEditor` 和对应 CSS 视觉层级
4. 保持节点属性数据结构兼容，避免本次变更引入存档迁移

## Open Questions

- 工具次级面板最终是与下方主编辑面板并列、抽屉式展开，还是附着在工具条侧边展开；这可以在实现时根据画布实际密度微调，但不影响本次规范落地
