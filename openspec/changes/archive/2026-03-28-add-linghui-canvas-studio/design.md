## Context

根目录的 `design.md` 实际上是一份 `LibTV 使用指南 / 操作手册`。如果只看画布相关内容，可以从中稳定反推出 LibTV 的核心工作流画布能力：

- 画布空白处双击即可新建节点
- 支持将图片、视频、音频文件直接拖入画布
- 画布存在 5 类基础节点：文本、图片、视频、音频、脚本
- 节点支持复制、粘贴、副本、删除、创建资产
- 选区支持打组，分组后可整体拖动、整组执行，并保存为“工作流”
- 画布存在“添加 / 工作流 / 资产 / 历史记录 / 教程”几个入口
- 画布存在小地图、缩放比例、快捷键面板
- 图片节点有 Slash 快捷功能、图像工具条；视频节点有视频工具条

结合当前灵绘实现，可以看到一个很明确的结论：

- 灵绘已经完成了一部分“画布最大化”工作，例如只保留顶部工具栏和中部画布，移除了常驻左栏/右栏/底栏
- 灵绘已经具备鼠标/手模式、右键菜单、框选、分组、节点弹窗、长按拖动等基础能力
- 但灵绘目前仍然更像“一个做过交互优化的 React Flow 画布”，距离 LibTV 的“工作流创作画布”还有明显差距

当前差距不在“再缩几个面板”，而在以下三个层面：

1. 画布入口与工作流复用能力不足
2. 节点与连线编辑能力不足
3. 画布级效率工具、调试工具与稳定性不足

因此，本设计不再延续旧版“固定四区壳层”的思路，而是改为一份**画布优先、以工作流复用为核心**的设计。

## Goals / Non-Goals

- Goals:
  - 让灵绘的交互心智从“节点编辑器”升级为“工作流画布”
  - 对齐 LibTV 操作手册中可确认的核心画布能力
  - 保持画布区域尽可能大，把高频能力收进右键菜单、抽屉、轻量工具栏和沉浸式工具
  - 用 5 类基础节点组织输入、生成、编辑和脚本驱动流程
  - 让“分组”升级为可运行、可复用、可保存的工作流块
  - 补齐画布最关键的效率能力：快捷键、复制粘贴、文件拖入、模板发送到画布、小地图、调试反馈
  - 拆分当前过于集中的画布状态，降低自动保存和重渲染互相干扰的风险
- Non-Goals:
  - 本轮不覆盖社区、发布、会员、消息中心等平台化能力
  - 本轮不覆盖完整模型市场、LoRA 市场和内容分发系统
  - 本轮不做多人协作和云端协同编辑
  - 本轮不实现完整 NLE 级时间轴剪辑器
  - 本轮不要求与 LibTV 在模型数量和工具数量上完全对齐

## Decisions

### Decision: 采用“画布优先”的最小壳层，而不是固定四区布局

旧设计将灵绘定义为“顶部工具栏 + 左侧节点库 + 中部画布 + 右侧属性面板 + 底部状态栏”的固定四区壳层。这和当前产品方向已经不一致：

- 用户明确希望画布尽可能大
- 当前灵绘实现也已经移除了常驻右侧/底部面板
- LibTV 手册中的很多能力本质上是“画布上的工具和入口”，并不要求常驻占位

新的壳层改为：

- 顶部：项目级最小工具栏，只保留工作区切换、命名、保存、导出、运行等能力
- 中部：无限画布作为唯一主区域
- 画布浮层：
  - 左上：项目菜单入口 / 命令入口
  - 右上：运行状态与队列入口
  - 左下：小地图与缩放比例
  - 右键菜单：添加、上传、运行、分组、复制粘贴等高频动作
- 抽屉层：
  - 添加
  - 工作流
  - 资产
  - 历史记录
  - 教程

**Why**

- 能保留 LibTV 手册里的能力入口，同时不牺牲画布面积
- 与当前灵绘已经完成的“隐藏常驻侧栏”方向保持一致
- 能让后续画布工具继续扩张，而不重新回到占屏面板设计

**Alternatives considered**

- 保留固定左栏/右栏/底栏：信息明确，但严重挤压画布，且与当前用户诉求冲突

### Decision: 重新定义基础节点模型，以 5 类基础节点为主

LibTV 手册中最稳定的节点心智是：

- 文本节点
- 图片节点
- 视频节点
- 音频节点
- 脚本节点

而当前灵绘节点模型更偏“生成任务节点”：

- 参考图
- 图片
- 视频
- 分镜
- 分镜组

新的设计改为：

- `文本节点`
  - 手动输入文本
  - 承载结构化提示词、剧情设定、描述文本
- `图片节点`
  - 可上传图片
  - 可作为生图结果节点
  - 可承载图像工具和 Slash 快捷能力
- `视频节点`
  - 可上传视频
  - 可作为生视频结果节点
  - 可承载视频工具
- `音频节点`
  - 可上传音频
  - 可承载音频生成结果
- `脚本节点`
  - 承载脚本结构化结果
  - 支持批量生成分镜图 / 视频

收口策略：

- `linghui/reference` 不再作为独立节点存在，统一收口到 `图片节点.import` 模式
- `storyboard-shot / storyboard-group` 不再保留兼容层，由 `脚本节点` 直接派生文本、图片和视频基础节点

**Why**

- 更符合 LibTV 的操作手册和用户心智
- 让“上传资源”和“模型生成结果”落在同一节点语义下，而不是割裂成“参考图节点”和“图片节点”
- 便于后续给节点挂载工具条、Slash 功能和资产操作

**Alternatives considered**

- 保持现有 `reference/image/video/storyboard` 节点模型：短期改动少，但会持续放大“引用节点”和“产物节点”割裂的问题

### Decision: 节点能力按“节点类型能力 + 节点操作能力 + 节点工具能力”三层设计

当前灵绘对“节点能力”的定义过窄，基本只覆盖：

- 节点长什么样
- 节点有哪些输入输出
- 节点弹窗里有哪些表单项

而 LibTV 手册里，节点能力至少分成三层：

1. 节点类型能力
   - 这个节点能承载什么内容
   - 这个节点支持哪些输入方式
   - 这个节点输出什么
2. 节点操作能力
   - 复制、粘贴、副本、删除、重命名、创建资产
   - 从当前节点继续拉出下游节点
3. 节点工具能力
   - 图片节点的 Slash、多角度、扩图、打光、重绘等
   - 视频节点的高清、解析、剪辑、合成等

新的设计因此不再只定义“有哪些节点”，而是为每类节点都定义完整能力包。

#### 节点能力矩阵

| 节点类型 | LibTV 手册推断能力 | 当前灵绘状态 | 设计结论 |
|---|---|---|---|
| 文本节点 | 手动输入、粘贴文本、语言模型生成文本 | 不存在独立节点；文本只嵌在图片/视频节点 prompt 中 | P0 补齐 |
| 图片节点 | 上传图片、拖图进画布、文生图、图生图、多图参考、图像工具条 | 只支持生成；上传靠参考图节点绕行；无工具条 | P0 补齐并重构 |
| 视频节点 | 上传视频、文生视频、图生视频、首尾帧、多模态参考、视频工具条 | 只支持基础图生视频；仅单参考入口；无工具条 | P0/P1 补齐 |
| 音频节点 | 上传音频、TTS、音乐/音效生成 | 不存在 | P0 补齐 |
| 脚本节点 | 基于剧情/角色图/参考视频生成脚本；批量出分镜图和视频 | 当前只有分镜节点/分镜组节点，能力远弱于脚本节点 | P0 补齐 |

#### 当前缺失的节点能力清单

下面这份清单专门回答“现在灵绘的节点能力还缺什么”，按节点逐项列出，不再停留在抽象方向。

##### 文本节点缺失

- 缺少独立文本节点实体
- 缺少手动输入 / 粘贴文本的画布节点入口
- 缺少基于 LLM 生成文本的节点能力
- 缺少文本节点结果预览与摘要展示
- 缺少文本节点作为上游提示词块、角色设定块、剧情块、镜头块的专门语义
- 缺少文本节点右键复制、副本、创建资产等节点级操作

##### 图片节点缺失

- 缺少“同一个图片节点既能上传又能生成”的统一模型
- 缺少直接把本地图片拖入画布后创建图片节点
- 缺少右键上传后直接生成图片节点
- 缺少多图参考融合的显式节点能力
- 缺少文本节点、脚本节点、图片节点共同驱动图片节点的清晰输入语义
- 缺少图生图与文生图在节点层的明确区分与切换
- 缺少节点顶部工具条
- 缺少 Slash 快捷动作入口
- 缺少图像工具能力入口：
  - 增强
  - 扩图
  - 多角度
  - 打光
  - 重绘
  - 擦除
  - 抠图
  - 标注
  - 裁剪
  - 宫格切分
- 缺少图片节点“创建资产”
- 缺少图片节点“副本保留上下文”
- 缺少图片节点多结果输出后的再加工入口

##### 视频节点缺失

- 缺少“同一个视频节点既能上传又能生成”的统一模型
- 缺少直接把本地视频拖入画布后创建视频节点
- 缺少文生视频节点心智
- 缺少首尾帧生成视频的专门模式
- 缺少多图、多视频、音频、文本共同驱动的视频节点输入模型
- 缺少多模态引用在节点层的显式用途配置
- 缺少节点顶部视频工具条
- 缺少视频工具能力入口：
  - 视频高清
  - 视频解析
  - 视频剪辑
  - 视频合成
  - 运镜预设 / 运镜提示
- 缺少视频节点和音频节点联合进入合成流程的节点级能力
- 缺少视频节点从解析结果继续派生脚本/分镜的能力

##### 音频节点缺失

- 缺少独立音频节点
- 缺少本地音频上传节点入口
- 缺少文字转语音节点能力
- 缺少音效 / 音乐生成节点能力
- 缺少音频节点结果预览、播放和摘要
- 缺少音频作为视频合成输入的节点语义

##### 脚本节点缺失

- 缺少独立脚本节点
- 缺少通过剧情描述生成脚本
- 缺少通过上传剧本生成脚本
- 缺少通过角色图生成脚本
- 缺少通过参考视频生成脚本
- 缺少结构化脚本结果展示
- 缺少表格视图 / 卡片视图 / 全屏视图
- 缺少字段显隐与筛选
- 缺少单条 / 批量勾选
- 缺少从脚本节点直接批量生成分镜图
- 缺少从脚本节点直接批量生成视频
- 当前 `storyboard-shot / storyboard-group` 只能覆盖很小一部分分镜能力，无法替代脚本节点

##### 所有节点的通用能力缺失

- 缺少统一的复制 / 粘贴
- 缺少“副本”和“复制”的区分实现
- 缺少 Delete 删除与 Undo/Redo
- 缺少节点右键“创建资产”
- 缺少从当前节点一键拉出下游新节点
- 缺少节点三层视图：
  - 折叠态
  - 轻编辑态
  - 沉浸式态
- 缺少节点复杂能力从弹窗迁移到工具条 / 沉浸式面板的机制
- 缺少节点级模板化与复用能力

#### 文本节点能力设计

- 输入方式：
  - 手动输入
  - 粘贴文本
  - 调用 LLM 生成文本
- 内容类型：
  - 角色设定
  - 剧情描述
  - 提示词块
  - 镜头说明
  - 结构化脚本片段
- 画布表现：
  - 折叠态显示标题 + 文本摘要
  - 展开态支持编辑器输入与 LLM 生成面板
- 输出：
  - `text`
- 节点操作：
  - 双击重命名
  - 复制 / 粘贴 / 副本 / 删除
  - 转为资产

#### 图片节点能力设计

- 输入方式：
  - 本地上传
  - 画布文件拖入
  - 右键上传
  - 上游文本/图片/脚本驱动生成
- 生成方式：
  - 文生图
  - 图生图
  - 多图参考融合
  - 宫格结果生成
- 节点内基础参数：
  - 提示词
  - 引用上游产物
  - 渠道 / 模型
  - 比例 / 分辨率 / 张数
- 节点级工具：
  - Slash 快捷功能
  - 多角度
  - 扩图
  - 打光
  - 重绘
  - 擦除
  - 抠图
  - 标注
  - 裁剪
  - 宫格切分
- 输出：
  - `image`
  - `images`
  - `grid`
- 设计约束：
  - 现有 `reference` 节点并入图片节点导入模式
  - 图片节点既能承载“输入图”，也能承载“生成结果图”

#### 视频节点能力设计

- 输入方式：
  - 本地上传视频
  - 上游图片 / 视频 / 文本输入
  - 首尾帧输入
  - 多模态参考输入
- 生成方式：
  - 文生视频
  - 图生视频
  - 首尾帧视频
  - 多参考视频
- 节点内基础参数：
  - 动态提示词
  - 上游引用
  - 模型 / 时长 / 比例 / 分辨率
- 节点级工具：
  - 视频高清
  - 视频解析
  - 视频剪辑
  - 视频合成
  - 运镜预设
- 输出：
  - `video`
- 设计约束：
  - 当前只有单图片参考输入，需要升级为多输入槽与多模态引用模型

#### 音频节点能力设计

- 输入方式：
  - 本地上传音频
  - 文本生成音效 / 音乐
  - 文本转语音
- 节点内基础参数：
  - 音频用途
  - 文本内容 / 风格
  - 模型 / 时长 / 音色
- 输出：
  - `audio`
  - `text`（可选，返回歌词 / 文案）
- 节点操作：
  - 与视频节点联合进入“视频合成”流程

#### 脚本节点能力设计

- 输入方式：
  - 文本剧情描述
  - 上传剧本
  - 上传角色图
  - 上传参考视频
- 节点内能力：
  - 生成结构化脚本
  - 表格视图 / 卡片视图 / 全屏视图切换
  - 字段显隐
  - 画面筛选
  - 单条或批量勾选
- 下游派生能力：
  - 生成分镜图
  - 批量生成视频
- 输出：
  - `script`
  - `shot-list`
  - `storyboard`
- 收口策略：
  - `脚本节点` 直接替代旧 `storyboard-shot / storyboard-group`
  - 需要保留的镜头描述由脚本节点派生到文本节点，而不是继续维护旧分镜节点

#### 节点通用操作能力

所有节点默认支持：

- 双击重命名
- 复制
- 粘贴
- 副本
- 删除
- 创建资产
- 从当前节点继续拉出下游新节点
- 查看结果
- 运行当前节点

其中“复制”和“副本”严格区分：

- 复制：只复制节点，不复制连线
- 副本：复制节点，并尽可能保留已有连线关系或配置上下文

#### 节点通用视图能力

所有节点默认具备三种视图层次：

- 折叠态
  - 只显示标题、状态、关键摘要、缩略图
- 轻编辑态
  - 在节点卡片内显示最常用参数
- 沉浸式态
  - 打开完整工具面板或全屏视图

这意味着复杂节点能力不应全部塞在悬浮弹窗中，而应按“频率”拆层。

### Decision: 统一空白画布入口，支持双击、右键和文件拖入三套创建方式

新的空白画布入口统一为：

- 双击空白：打开快速创建器
- 右键空白：显示“添加节点 / 上传文件 / 粘贴工作流 / 运行 / 视图”菜单
- 直接拖入本地文件：
  - 图片 => 创建图片节点（导入模式）
  - 视频 => 创建视频节点（导入模式）
  - 音频 => 创建音频节点（导入模式）
  - JSON / 工作流包 => 导入工作流

快速创建器默认提供：

- 文本
- 图片
- 视频
- 音频
- 脚本
- 最近使用节点
- 最近使用工作流模板

**Why**

- 双击创建和拖文件导入是操作手册里最明显的低门槛入口
- 能显著减少“先打开某个面板再创建”的路径长度
- 与当前右键菜单能力形成互补，而不是替代

### Decision: “分组”升级为“工作流块”，并增加工作流保存/复用

当前分组只是视觉容器，缺少以下关键能力：

- 保存为工作流
- 从工作流库重新发送到画布
- 整组执行
- 作为局部模板复用

新的分组语义升级为“工作流块”：

- 框选后可创建分组
- 分组可命名、拖动、取消分组
- 分组可保存为工作流模板
- 工作流模板可从“工作流抽屉”重新发送到画布
- 工作流块支持整组执行
- 后续可扩展为“子流程 / 子图”

这一定义故意不一步做到 ComfyUI 的 Subgraph 节点，而是分两层：

1. 第一层：可见分组 + 可保存模板 + 可整组运行
2. 第二层：可折叠为子流程节点 + 可具名输入输出端口

**Why**

- 这条路径最贴近 LibTV 手册里的“打组 -> 创建工作流 -> 发送到画布”
- 可以在不一次性引入复杂子图系统的前提下，先补足工作流复用能力

### Decision: 右键菜单与快捷键成为画布主要操作入口

当前灵绘右键菜单已经存在，但能力偏轻。新的右键体系需要覆盖：

- 节点右键：
  - 复制
  - 粘贴到相邻位置
  - 副本
  - 删除
  - 创建资产
  - 从当前节点新建下游节点
  - 运行当前节点
- 选区右键：
  - 创建分组
  - 取消分组
  - 保存为工作流
  - 批量复制
  - 批量删除
  - 运行选中
- 画布右键：
  - 添加节点
  - 上传文件
  - 粘贴工作流
  - 打开工作流抽屉
  - 打开资产抽屉

同时引入快捷键体系：

- `Ctrl/Cmd + C/V`：复制 / 粘贴节点或选区
- `Delete / Backspace`：删除选中
- `Ctrl/Cmd + G`：创建分组
- `Ctrl/Cmd + Shift + G`：取消分组
- `Ctrl/Cmd + Z / Shift + Cmd + Z`：撤销 / 重做
- `Space`：临时手模式
- `Tab` 或 `/`：打开命令面板 / 快速动作面板
- `F`：聚焦当前选区

**Why**

- 这条路径最能体现“专业工作流画布”的效率感
- 当前灵绘的复制、撤销、粘贴、删除都未成为一等能力，是最明显的短板之一

### Decision: 引入“画布抽屉”而不是常驻左栏，承载工作流、资产、历史和教程

LibTV 手册里的左侧栏有 5 类能力：

- 添加
- 工作流
- 资产
- 历史记录
- 教程

在灵绘里，这些能力保留，但全部改成可开关抽屉或命令面板：

- 添加抽屉：节点分类、上传入口、最近常用
- 工作流抽屉：已保存工作流、最近模板、发送到画布
- 资产抽屉：图片/视频/音频/Text 资产，支持发送到画布
- 历史抽屉：最近生成结果，支持回到画布继续使用
- 教程抽屉：画布快捷帮助、节点说明、快捷键列表

**Why**

- 既保留了操作手册中的“功能完备性”，又不破坏画布最大化
- 这比把所有能力继续塞进右键菜单更清晰

### Decision: 图片节点和视频节点采用“上下文工具条 + 沉浸式工具面板”

LibTV 手册里很多不是“节点类型”，而是“节点上下文工具”：

- Slash 快捷功能
- 图像工具：增强、扩图、多角度、打光、重绘、擦除、抠图、宫格切分、标注、裁剪
- 视频工具：高清、解析、剪辑、合成

因此，新的设计不把这些全部做成单独节点，而采用两层结构：

- 节点主卡片负责承载资源、提示词、执行状态和基础参数
- 节点工具条负责打开对应的沉浸式工具面板

例如：

- 图片节点顶部显示轻量工具条
  - Slash
  - 多角度
  - 扩图
  - 打光
  - 重绘
- 视频节点顶部显示轻量工具条
  - 高清
  - 解析
  - 合成

工具面板优先采用覆盖式/沉浸式交互，而不是把复杂 UI 再塞回节点弹窗。

**Why**

- 能避免节点卡片继续膨胀
- 更接近 LibTV 手册中“选中节点后弹出顶部工具”的交互模型

### Decision: 小地图、缩放比例和运行反馈成为轻量常驻浮层

新的常驻浮层只保留三类信息：

- 小地图
- 当前缩放比例
- 运行/队列状态入口

不再恢复旧版“底部状态栏 + 右侧日志面板”。

日志、失败信息和历史生成结果统一进入可打开的浮层或抽屉。

**Why**

- 小地图和缩放比例是画布导航能力的一部分，属于必须常驻但必须轻量
- 日志和历史不是必须常驻的高频信息，不值得长期占画布空间

### Decision: 文档状态和 UI 暂态分层，避免自动保存导致画布重渲染

当前 `LinghuiCanvas.tsx` 同时承担：

- 文档节点与连线
- 右键菜单
- 选区
- 待分组框
- 节点编辑弹窗
- 模式切换
- 快照发射与自动保存

后续继续叠加模板、快捷键、文件拖入、小地图、历史抽屉，会让它更脆弱。

新的状态分层：

- 文档状态：
  - nodes
  - edges
  - groups
  - workflow templates
  - asset references
- UI 暂态：
  - selection
  - viewport
  - context menu
  - active tool
  - command palette
  - drawer visibility
  - drag/press state
- 运行态：
  - queue
  - node run state
  - last outputs
  - execution trace

自动保存只订阅文档状态，不订阅 UI 暂态。

**Why**

- 这是避免“自动保存导致画布重新渲染”的根本手段
- 也方便把画布能力拆成多个模块，而不是继续堆在一个大组件里

### Node Data Model Evolution

```ts
type LinghuiNodeKind = 'text' | 'image' | 'video' | 'audio' | 'script';

interface LinghuiTextNodeProperties {
  sourceMode: 'manual' | 'llm';
  content: string;
  promptTemplate?: string;
  llmConfigId?: string;
}

interface LinghuiImageNodeProperties {
  mode: 'import' | 'generate';
  prompt: string;
  negativePrompt?: string;
  references: string[];
  providerId?: string;
  modelId?: string;
  aspectRatio?: string;
  resolution?: string;
  batchCount?: number;
}

interface LinghuiVideoNodeProperties {
  mode: 'import' | 'generate';
  prompt: string;
  inputMode: 'text-to-video' | 'image-to-video' | 'first-last-frame' | 'multi-modal';
  references: string[];
  providerId?: string;
  modelId?: string;
  duration?: number;
  aspectRatio?: string;
  resolution?: string;
}

interface LinghuiAudioNodeProperties {
  mode: 'import' | 'tts' | 'music' | 'sfx';
  text?: string;
  voiceId?: string;
  duration?: number;
  providerId?: string;
}

interface LinghuiScriptNodeProperties {
  sourceMode: 'story' | 'script' | 'character-image' | 'reference-video';
  prompt: string;
  sourceText?: string;
  references: string[];
  viewMode: 'table' | 'cards' | 'fullscreen';
  visibleFields: string[];
  filters: Record<string, unknown>;
}
```

设计原则：

- 节点 `kind` 决定节点语义
- 节点 `mode` 决定具体输入或执行模式
- 所有媒体节点都统一支持 `import / generate`
- 所有复杂工具都通过节点上下文工具挂载，而不是继续拆出大量碎片节点

### Clipboard and History

- 引入画布级 clipboard 数据结构
- 引入文档级 undo / redo 历史栈
- 节点复制与“副本”区分：
  - 复制：复制节点本体，不保留连线
  - 副本：复制节点本体并尝试复制内部连线关系

### Workflow Templates

- 工作流模板本质上是一个可复用的 group + nodes + edges 快照
- 支持保存到工作流抽屉
- 支持一键发送到画布指定位置

### Suggested Module Split

- `LinghuiCanvasDocumentStore`
  - nodes / edges / groups / templates / assets
  - undo / redo
  - persistence snapshot
- `LinghuiCanvasUiStore`
  - selection
  - context menu
  - quick create
  - drawers
  - active tool
  - viewport affordances
- `LinghuiExecutionStore`
  - queue
  - node runs
  - execution trace
  - stale detection
- `LinghuiClipboardService`
  - copy
  - paste
  - duplicate
- `LinghuiImportService`
  - file drop to node
  - workflow import
  - history result rehydrate

### Interaction Priority

为了保证实现节奏可控，节点交互按优先级分层：

1. P0 高频基础交互
- 创建节点
- 拖入文件
- 复制 / 粘贴 / 删除
- 运行当前节点
- 工作流保存 / 发送到画布

2. P1 高频创作交互
- 图片工具条
- 视频工具条
- 脚本批量派生
- 历史结果再利用

3. P2 深水区交互
- 完整时间轴视频合成
- 高级运镜控制
- 节点资产市场化

## Implementation Phases

### Phase 1: 画布交互基本盘

- 双击空白快速创建
- 文件拖入自动建节点
- 右键菜单增强
- 复制 / 粘贴 / 副本 / 删除 / Undo / Redo
- 小地图与缩放比例

### Phase 2: 基础节点体系重构

- 新增文本节点、音频节点、脚本节点
- 将参考图节点并入图片节点导入模式
- 统一图片/视频节点的上传与生成双模式

### Phase 3: 分组升级为工作流块

- 保存为工作流
- 工作流抽屉
- 发送到画布
- 整组执行

### Phase 4: 上下文工具体系

- 图片节点工具条
- 视频节点工具条
- Slash 快捷面板
- 沉浸式工具视图

### Phase 5: 稳定性和调试

- 运行路径高亮
- 失败节点快速跳转
- 自动保存与 UI 状态彻底解耦
- 画布状态模块化拆分

## Risks / Trade-offs

- 完全移除旧 `reference / storyboard-*` 节点后，历史工作区若仍包含这些节点将不再作为受支持路径
  - Mitigation: 新版实现只维护 5 类基础节点，避免继续扩大兼容面与维护成本
- 增加 5 类基础节点后，节点系统会短期更复杂
  - Mitigation: 先收敛为统一节点壳层和统一操作模型
- 右键菜单、快捷键、抽屉、命令面板同时增加，交互入口会变多
  - Mitigation: 明确主路径为“右键 + 双击 + 文件拖入”，抽屉只承载库类能力
- 分组升级为工作流块后，文档模型会复杂化
  - Mitigation: 先把模板保存做成 group snapshot，不立即引入真正 subgraph

## Rollout Notes

1. 新版画布和节点库只保留 5 类基础节点
2. 旧 `reference / storyboard-*` 节点不再继续维护兼容链路
3. 脚本节点的镜头派生统一落到文本、图片、视频基础节点
4. 分组数据先保持现有结构，再增加工作流模板引用层

## Open Questions

- `创建资产` 首版是否只保存媒体资源，还是同时允许保存“节点 + 参数快照”？
- 工作流模板发送到画布时，默认是否携带原有坐标布局？
- Slash 快捷功能首版只覆盖图片节点，还是同步给视频节点提供 `/补帧`、`/高清` 一类动作？
