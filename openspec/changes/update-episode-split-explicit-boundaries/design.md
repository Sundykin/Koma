## Context
- 当前自动剧集入口会直接调用 `EpisodeSplitService.analyzeScript()` 交给 LLM 规划剧集。
- 现有本地切分逻辑只消费 LLM 返回的 `splitPoints`，不会主动解析剧本原文中的现成分集边界。
- 用户导入的剧本可能已经是完整长剧拆分稿，含有明确集号、场号或复合标题格式；此时继续让 LLM 重规划会破坏原始结构。

## Goals / Non-Goals
- Goals:
  - 原文存在显式分集边界时，优先按原文切分
  - 原文不存在显式分集边界时，保留现有 LLM 规划能力
  - 减少用户填写目标集数后却被模型随意改写的行为
- Non-Goals:
  - 不在本次变更中处理角色/场景/道具提取性能问题
  - 不在本次变更中支持用户手动拖拽分割点

## Decisions
- Decision: 在 `EpisodeSplitService` 之前增加 deterministic parser，先扫描原文显式边界
  - Why: 这类信息已经存在于用户输入里，不应再交由 LLM 猜测
- Decision: 命中边界后直接生成切分结果或最小化蓝图，不让 LLM 决定 `suggestedCount`
  - Why: 用户原文结构的优先级高于模型建议
- Decision: 未命中边界时，保留现有 LLM 流程，但提示词改为“若用户指定目标集数，则按该数量输出；仅在未指定时自行判断”
  - Why: 降低“目标集数只是建议值”的歧义

## Risks / Trade-offs
- 风险: 剧本中的集号样式可能很多，初版规则可能漏识别
  - Mitigation: 先覆盖高频格式（`第X集`、`第X话`、`104-1`、纯集号标题），并补测试样本
- 风险: 某些文档中的“第X集”可能出现在对白或注释中，误判为分界
  - Mitigation: 要求边界标记位于行首或独立标题行，并结合后续场景行模式交叉验证
- 风险: 命中显式边界后，`targetEpisodeCount` 与原文边界数量不一致
  - Mitigation: 以原文边界数量为准，并在 UI 上明确提示“已按原文分集结构拆分”

## Migration Plan
1. 增加显式边界解析 helper
2. 在自动剧集服务中先调用边界解析
3. 命中边界则走确定性切分，未命中才回退到 LLM 分析
4. 更新提示词与 UI 文案
5. 增加回归测试

## Open Questions
- 是否需要在 UI 上新增“优先按原文分集”开关，还是直接作为默认行为
- 当原文边界数量与用户输入目标集数冲突时，是否只提示，还是阻止继续
